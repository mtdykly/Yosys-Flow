# SQLite / gzip 的 ANUBIS 与 EPFL 对比

后续针对本页 B 项的修复及每项一次复测见 [来源证据补齐后的结果](backend-support-comparison.md)。本页保留修复前的两次测量，不覆盖原始失败和时间数据。

本轮基于检查点 `9185d97` 的正式双后端实现。SQLite 与 gzip 使用相同的去重行表、共享字段、来源证据和选区算法；默认后端仍是 SQLite。运行目录为 `runs/backend-suite-360/`，构建和测量入口的变动在各套件 `implementation/` 中冻结，实际原始证据、工具和输入都有哈希。

## 范围与口径

- ANUBIS 沿用有功能修改的组合适配案例 `compare_local9`、`control_local2`，各测保留层次和展平。无功能变化及状态负例不纳入主性能比较；这不是整个 ANUBIS 仓库的覆盖率。
- EPFL 使用固定上游版本的 `ctrl.v`、`router.v`、`priority.v`、`adder.v`、`bar.v`、`arbiter.v`。每个原始电路构造 `local`、`shared` 两种单运算符修改，共十二对。修改位置在结果产生前固定，SAT 顶层反例和独立源图回放确认确实改变功能。详见[基准清单](../benchmarks/epfl/README.md)。
- 每个后端、案例、模式、方法均重复 **2 次，报告算术平均数**。旧版本普通综合、插桩综合及建档也独立重复两次；在线重复与旧归档按轮次配对。同一个 EPFL 旧电路在同一轮内供两种修改共享，不重复计算为两次独立建档。
- 每个隔离作业墙钟上限 **360 秒**，不设置文件字节上限。串行固定同一个 CPU、固定线程环境，方法与在线重复按同一个随机种子打乱。没有清空操作系统页缓存，不声称测量冷磁盘访问。
- `F` 从完整新版 RTL 执行原版 Yosys 完整 `synth`；`P-module` 用相同来源系统按模块选区；`P-fine` 使用自动细粒度差分、扩区、patch 综合和拼接。`P-module` 不是独立的模块级增量算法 M。
- 主时间从完整新版 RTL 和旧归档开始，到完整新版 generic JSON/RTLIL/Verilog 写出为止。旧建档不计入在线时间；选区所需的证据检查和边界判定属于算法成本。生成后的整网表等价及读回验证另外统计，不计入主时间。
- 面积采用相同 Nangate45 typical Liberty 对**完整最终网表**统一映射，累加所有映射单元的库面积，单位 µm²。它是工艺库估计，不是布局布线面积；还没有宣称复用旧标准单元映射。映射时间单列，同时提供“generic 生成 + 工艺映射”的时间。
- 失败、来源不足、超时都保留。只有同组 **2/2** 完成并通过后验验证才报告成功生成均值与面积；失败尝试时间不会充当成功生成时间。作业预算也包括后验验证和面积检查，故不能把总作业超时直接解释为综合耗时 360 秒。

物理行数包含注释和空行；ANUBIS 递归统计入口实际包含的唯一文件，包含宏头文件一次，区分旧版和新版。`compare_local9` 的来源叶模块自身只有 55 行，完整适配案例还包含顶层、旧/新叶模块及宏定义。因此行数、布尔门数和实际难度要结合看。

“原记录”是 `yosys.jsonl` 加全部 `.abc_*` 证据文件；“索引”是 `verified-index.sqlite3` 或 `verified-index.json.gz`；“归档”是 `base-run/` 下全部逻辑字节，已经包含前两项、网表、脚本与验证产物，不能再次相加。MiB = 1,048,576 字节。超时目录仅代表已写出的部分产物，索引为零表示未完成构建。

“索引构建秒”是验证完成后写出归一化索引的阶段，不包括先前的记录重放与验证；这些分别位于完整指标文件的 `offline_record_validation_seconds` 和 `offline_replay_and_index_seconds`。旧建档总时间包含全部阶段及进程开销。

## 复现

```bash
python3 -m incremental.epfl fetch

# backend 分别取 sqlite、gzip；输出目录必须不存在。
python3 -m incremental compare --suite anubis-functional --mode both \
  --methods F P-module P-fine --index-backend sqlite \
  --repeats 2 --baseline-repeats 2 --job-timeout 360 \
  --liberty build/technology/nangate45/lib/NangateOpenCellLibrary_typical.lib \
  --yosys /opt/oss-cad-suite/bin/yosys \
  --out runs/backend-suite-360/sqlite/anubis

python3 -m incremental compare --suite epfl-functional --mode retained \
  --methods F P-module P-fine --index-backend sqlite \
  --repeats 2 --baseline-repeats 2 --job-timeout 360 \
  --liberty build/technology/nangate45/lib/NangateOpenCellLibrary_typical.lib \
  --yosys /opt/oss-cad-suite/bin/yosys \
  --out runs/backend-suite-360/sqlite/epfl
```

每个后端预定 24 个 ANUBIS 在线样本和 72 个 EPFL 在线样本，两后端合计 192 个。这是方法、模式、修改和重复展开后的样本数，不是 192 个独立电路。每个后端另外有 20 次独立旧建档（8 次 ANUBIS、12 次 EPFL）。基线超时导致的在线未启动行也保留在分母中。

## 完整指标

- `runs/backend-suite-360/summary.json`：按后端、案例和模式合并的来源规模、建档、在线时间、面积、内存、失败原因及原报告哈希。
- `metrics.csv`：两张表之外的完整指标，包括原始 Yosys/ABC 字节、索引描述文件、归档文件数、旧网表门数、复用比例、映射时间和后验验证时间。
- `stages.csv`：每次在线运行的阶段耗时，保留加载、差分、选区、patch、局部综合和拼接等字段；父计时与子计时可能重叠，不能全部相加。
- 每个后端各自的 `anubis/`、`epfl/` 下保留 `report.json`、`timings.csv`、`stages.csv`、冻结源码、工具与库哈希、作业日志和所有成功/失败产物。

## 实测结果

四批实验均完成，冻结实现、工具和输入校验通过。两个后端的每项成功/拒绝分类、成功网表门数、选区/复用结果及映射面积一致。新增测量入口的 63 项专项单元测试通过、零跳过；跨报告核对通过。这些检查数不是独立电路数。

192 个预定在线测量组合中：64 次 F 成功、4 次 P-module 成功、8 次 P-fine 成功；100 次增量尝试因来源/边界证据不足拒绝，16 次因旧建档不可用而未启动。没有在线超时或面积映射失败。40 次独立旧建档中 36 次完成、4 次 `arbiter` 在 360 秒超时，均未生成可用索引。

## 结果的含义

本轮有效的增量比较仅覆盖保留层次的 `compare_local9`（P-module、P-fine）与 `adder_local`（P-fine）。这些成功路径都比对应 F 慢，没有测得在线生成时间收益；失败路径不计算加速比。

gzip 在本轮所有已完成建档上都略快，索引文件也更小，但在线速度并不统一领先。例如 `compare_local9` 的 P-fine 是 SQLite 1.727 秒、gzip 1.605 秒；其 P-module 则是 SQLite 0.652 秒、gzip 0.748 秒。`adder_local` 的 P-fine 是 SQLite 6.725 秒、gzip 8.066 秒，峰值进程树 RSS 约 133 / 443 MiB，旧归档加载约 0.234 / 1.277 秒。此处包含哈希检查、索引打开和电气视图恢复，不是冷磁盘读取。

`adder_local` 两边约 5 秒花在新旧中间表示差分上。`bar` 的记录验证约 46.6 秒，与后端无关；其索引写入均值则为 SQLite 27.744 秒、gzip 20.968 秒。索引后端影响存储、加载与查询，不能消除来源证明不足，也没有解决 `arbiter` 在索引构建之前的离线验证超时。

失败分布在两后端完全一致：ANUBIS 展平的 `compare_local9` 为来源候选；`control_local2` 两种模式还存在连接消费者未完全绑定。EPFL 除 `adder_local` 的 P-fine 外，`ctrl/router/priority/adder` 的增量尝试均因来源候选拒绝；`bar` 还缺少全部输出功能证明。`arbiter` 的两个修改均因旧建档超时没有启动增量。

失败成本同样保留。例如 `bar_local` 的 P-module 尝试均值 SQLite / gzip 为 75.527 / 74.770 秒，P-fine 为 104.984 / 101.151 秒；它们都未交付网表，不能把这些数字作为成功的生成时间。两次重复仅是本轮工程测量，不能据此推断普遍或统计显著的优势。

完整结果位于 `runs/backend-suite-360/`：`experiment.json` 保存计数及汇总文件校验和，`checks.json` 保存跨报告核对，`summary.json` / `metrics.csv` 保存两表以外的全部指标。四份原始报告还保留每次测量、失败日志、后验检查及证据哈希。运行产物仍被 Git 忽略；本文、基准清单与测量入口可提交。
