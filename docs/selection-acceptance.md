# 组合逻辑的来源选择验收

目标保持为“原始组合 RTL → 完整默认 synth → 原始语句关联的最终逻辑 → 子网表导出”。所有验收使用固定工具与默认 ABC，不添加 keep。时序实现与正向时序用例已移除；输入拒绝检查另行保留。

已验证的共享门组是合法的验收粒度，无须强行把组内每个门独占分配给某一行。来源规则、共同功能范围和应包含/排除的对象必须明确；候选单列范围依据和未证明原因。完整 ABC 因果历史不作为本阶段所有结果的共同前提，也不能因接受门组就把候选提升为已证明。

## 可复现例子

```bash
make NATIVE_JOBS=4
python3 -m yosys_flow run --source examples/selection.v --top demo --out runs/selection-demo
python3 -m yosys_flow query runs/selection-demo --source examples/selection.v --line 2
python3 -m yosys_flow extract runs/selection-demo --source examples/selection.v --line 2 --out runs/selection-demo/and.v
python3 -m yosys_flow extract runs/selection-demo --source examples/selection.v --line 3 --out runs/selection-demo/xor.v
```

第 2、3 行的独立 AND/XOR 输出分别选择自己的最终门；共享表达式仍保留多个来源。它们即使在同一次 ABC 调用中，也不因区域并集而互相混入。

`examples/comb.v` 演示组合 always、直连和常量；`examples/process_precision.v` 演示嵌套分支、覆盖赋值和部分位覆盖；`examples/chain.v` 演示同一输出锥内两条语句的局部切点分离。运行目录和导出文件不可覆盖，重复实验请换目录。

## ABC 证据与候选含义

提取时捕获真实信号编号、输入节点 fanin、节点对应的退休 cell 和输出边界。导入时记录 BLIF cell 的类型、端口、映射到用户设计的实际端口，以及边界连接。读取器与归档的输入/输出 BLIF、首次对象状态交叉核对。

细化为每个保留输出求映射前的输入成员锥，以及映射后服务该输出的门。共享门保留多个输出的来源并集。该算法在 `yosys_flow/abc_provenance.py`，结果为 `abc_output_cone_candidate`，证据放入 `abc_associations`。

现在还读取固定 ABC 的内部日志。单门切点验证通过时使用 `abc_internal_cut`；多门整体证明使用 `abc_internal_joint_cut` 并保留组内来源并集，不能将其当成逐门独占归属；未证明的门继续使用上述候选。实际 AIG 替换和选中映射已有钩子，完整内部重写历史尚未建立，因此 `internal_rewrite_provenance=false`、`end_to_end_exact=false` 保留。未知门或无法解析的输出回退 `abc_region_candidate`，原因位于 `abc_refinement_fallbacks`；内部验证的规模/接口限制另见 `abc_internal`。详见 [abc-internals.md](abc-internals.md)。

原始 JSONL 先按真实区域来源并集重放，再建立查询投影；细化不改写原始记录。多来源关系不能无依据地提高精度。

## 组合优化的实际事件

`cell_contribution` 表示存活供体实际贡献到目标新版本，供体不因此自动退休。当前保留 `opt_reduce_import`，在实际成功合并子归约的位置取来源并集。`opt_muxtree_prune` 记录实际裁剪目标与替代连接；全部条件分析的跨对象依据仍未覆盖。

`techmap_bit_map` 保存原输出位和实际生成对象输出位及双方信号，用于核对拆分边界；它不自动证明算术内部门的位级来源。组合过程细节见 [process-provenance.md](process-provenance.md)。

## 验收方法

`tests/test_selection.py` 使用最终输出端点、独立逻辑锥和应排除的对象定义预期，不用记录器自己的来源并集生成答案。检查共享、候选精度、原始记录不可变、ABC 节点/归档损坏，以及实际导出。

`tests/test_combinational.py` 验证组合 always 被保留，时钟过程、初始化、推导锁存器和组合环路不能发布成功结果。`tests/test_native.py`、`tests/test_process.py` 保留组合过程和开发检查点测试；`tests/test_synth.py` 验证完整默认终点，`tests/test_export.py` 验证边界、常量、参数和共享。

三层验收分别是记录一致性、来源选择正确性、导出正确性。运行还对照独立原版的完整 JSON modules 并验证功能等价；这些检查不能把未捕获转换认定为已覆盖。

`make test` 通过 `tools/run_regression.py` 保存完整报告和日志，记录工具版本、提交/工作区身份、测试清单及失败/跳过详情。验收层与测试模块的对应单独列出，某个模块通过不意味着其所属层的全部来源场景已覆盖。完整回归要求零跳过。

`tests/test_abc_internal.py` 专门检查同输出组合链、共享中间逻辑、极性、实际替换记录、内部证据损坏，多级重结合的组级包含/排除、共享边界、嵌套条件、实际 fraig/dch 等价/choice、损坏极性/复制/计数，以及缺少证明依据和超出证明规模后的候选回退。

`tests/test_abc_factoring.py` 为新的等价表达式门组定义以下独立预期；不以记录器自己的来源集合生成期望值。

| 用例 | 必须包含 | 必须排除或拒绝 |
| --- | --- | --- |
| `(a&b)|(a&c)` 与 `a&(b|c)` | 任意一行均选择最终共享 AND、OR，两行来源并集 | 独立输出 XOR；不允许漏掉共享 OR |
| 公共上游 `a=s&t` 作为输出保留 | 两种等价写法均选择下游两门，导出以 `a,b,c` 为输入 | 上游 `s&t` 的门及独立输出 |
| 正反相等价输出 | 实际 AND、NAND、OR 共享组，保留原根与复制链极性 | 独立输出 XOR |
| 输出门复制后再合并 | 所有副本都有真实复制证据，最终共享来源和精度保留 | 因未记录副本而退回候选 |
| 仅函数相同、没有已记录合并 | 不产生新的等价门组 | 不得仅凭函数匹配提升精度 |
| 损坏入口或副本证据 | 拒绝非法极性、缺项、断链、绑定、计数及不完整副本表 | 函数相同但未采用的 sweep 目标也必须拒绝 |
| ABC 将整个区域化为 0/1 | 零 cell 模块和实际常量输出，综合/导出验证通过 | 不得引用已退休常量对象或无依据地提升连接精度 |

导出另检查两门集合、实际边界位及 Verilog 重读等价，反查检查两行共享来源。结果继续报告 `end_to_end_exact=false`；门组证明不计作组内逐门独占归属或完整内部历史。示例及命令见 [ABC 因式分解门组](abc-internals.md#等价表达式与因式分解门组)。

## 后续 ABC 钩子的案例验收（待扩展）

每项新增记录先保存最小 RTL、固定脚本、现有结果与具体问题：是漏选/多选、边界不完整、回退原因无法解释，还是某段实际转换缺少可校验连接。随后定义独立的预期门集合或门组及边界，再决定钩子位置。当前优先调查 fraig 清理、`dc2` 和 `&dch` 周围的网络转换；这里列的是调查方向，不表示已经发现每一处都会导致查询错误。

验收同时包含正向查询、对象反查、共享使用者、边界导出，以及移除/破坏新增证据时的拒绝或明确回退。原版默认 synth 结果保持一致。只增加事件、通过导出等价或缩小候选数量，均不能单独证明来源选择正确。

## 区域替换适用性实验（暂缓）

这是后续独立研究项，当前暂缓，不作为本轮或层次扩展的必需前置验收。现阶段优先完善旧记录的区域对应和约束。未来实验首轮使用显式提供的新旧语句/端点映射和完全定义的二值组合逻辑；不要求自动 RTL 差分。实验不得用旧网表选择结果直接推断新版依赖。

| 场景 | 实验必须验证 | 不足时的处理 |
| --- | --- | --- |
| 修改 `multilevel.v` 中的 `u` | 共同重建 `u/y` 相关区域，绑定实际 `t` 信号及极性、`c/d`；保留上游 AND、独立 OR 及其使用者 | 新依赖不能在旧边界中表达时扩大区域或拒绝 |
| 仅修改 `factoring.v` 中的 `y` | `z` 保持旧功能，独立输出保持不变；逐个对外消费者绑定，必要时把旧共享信号拆为不同的新信号 | 缺少端点对应时报告信息不足，禁止整体替换旧电气位而连带改变 `z` |
| 新版引入旧边界以外的输入 | 显式识别新增依赖及所需边界变化 | 禁止静默丢弃依赖或继续声称旧区域适用 |
| 候选来源、错误极性、遗漏输出或错误拼接 | 适用性分析或最终证明必须揭示问题；超时保留未证明 | 不得仅凭原查询/导出验证通过发布替换成功 |

保存旧/新 RTL、完整功能端点清单、旧区域、局部 RTL 与网表、新旧端点绑定、拼接网表及验证脚本/日志。局部网表由给定局部 RTL 生成；新版完整默认 synth 的结果只作为整体验证参考，不能从中摘取结果冒充局部重综合。

验收比较拼接设计与新版参考设计的全部可观察输出，并检查保留区域、跨边界使用者、单驱动和无组合环。功能等价允许网表结构不同。实验结果分别报告信息不足、需扩大区域、失败、超时/未证明、特定版本对验证成功；现有来源报告中的 `safe_for_incremental_reuse=false` 不因个例成功而自动改为 true。

## 证明规模与记录成本（已解除区域输入数硬限制）

`tools/benchmark_abc.py` 的共享链使小目标与更大的下游逻辑处于同一 ABC 区域，工具核对实际提取后的区域输入数，不能只按 RTL 顶层端口数分组。当前大区域的阶段函数及大于 10 输入的独立切点使用 ROBDD，10 仅为选择真值表的阈值。

- 规模覆盖 8、10、12、16、32 个区域输入，并单独包含“大区域中的小局部切点”和共享/重结合较多的案例；不能只增加互不相关的小输出。
- 记录最终 cell 数、选中/候选对象数、已证明单门/门组数、回退原因、事件和快照数量、日志总字节数及峰值内存。
- 分开计量原版综合、带记录综合、日志读取/证明、查询和导出耗时；当前 `run` 还包含独立对照与等价验证，不能把其总耗时直接作为插桩开销。
- 固定工具、源码和脚本摘要，记录机器、并发配置、重复运行次数及中位数。保持原版结果对照和三层正确性检查，性能收益不能掩盖精度退化。

符号证明必须保留跨网络输入绑定、极性和切点独立性的依据，不能简单截掉依赖后判相等。区域预算耗尽保留候选；局部尝试耗尽预算只取消该尝试，保留其他证明及未证明候选。后续根据更复杂函数的节点/计算量决定局部验证分解、SAT 或减少重复快照；当前尚未实现 SAT，也未消除复杂全域函数造成的整体回退。

旧基线中，12/16/32 输入时，一个门的目标分别返回 11/15/31 个候选门，原因为 `input_limit_exceeded`。新验收要求这些区域中的 `t` 和 `small` 语句各只返回自己的一个门；下游 `y` 的选择排除上游两门，来源、反查和独立边界均符合预期。所有规模案例都要求 `exact_cell_selection` 且没有候选，多选不再作为该里程碑的可通过状态。运行和字段见 [abc-diagnostics.md](abc-diagnostics.md)。

`tests/test_diagnostics.py` 验证从已有记录诊断时没有外部工具调用、不会修改运行产物；共享输出 `y/z` 必须同时列出；单独查询一个门组成员会报告其他必需成员，且不暗中扩张选择；遗漏输出/消费者或损坏记录会被发现。还检查源码变更提示、常量值不被当成共享电气身份，以及规模采样要求独立精度预期。

`tests/test_boolean.py` 穷举全部三输入布尔函数，对照符号运算，并检查所有支持的节点类型、极性、输入重排和宽独立边界的相关性反例。`tests/test_abc_scale.py` 执行真实默认 synth，验收 12/16/32 输入选择与导出、离线查询、区域/局部预算失败，以及大区域的阶段函数、极性和 PI 复制损坏。预算不足是未证明，不能伪装成反例或成功。

## 区域契约验收（首轮已实现）

契约独立验证层不替代前面的记录、来源选择与导出三层。`tests/test_contracts.py` 包含 18 项测试，验收如下：

- 两级链的局部输入及极性正确；合并后消去区间输入，并在原始输入所有取值上符合例子的独立 RTL 功能预期。
- `factoring.v` 的共享输出同时保留 `y/z`；`multilevel.v` 的单对象契约显式补齐记录门组；32 输入案例仍只选择目标门。
- 每个对外输出都验证，包括中间结果被未选中门使用；故意只损坏次要输出也必须失败。
- 重叠/嵌套合并取并集、去重，重新计算共享义务、内部化端口和外部返回路径；添加中间区域后重新计算条件。
- 常量依靠原始端点身份；直连区域合入驱动后，仍在使用的输出不能被错误标成已内部化。
- 来源候选在旧函数验证通过后仍为 partial；不支持的二值函数或证明预算不足不能报告函数已证明。
- 对输出、消费者、函数、极性、来源边、扩展集合、父契约或合并说明的篡改，即使重新计算哈希也被拒绝；不同运行禁止合并。
- 离线契约命令禁止外部进程并保留原始运行文件；源码变更提示仅影响当前适用性，不改写旧记录。
- 合并契约实际导出 Verilog，并通过已有网表和重读等价验证。

本轮完整回归：`runs/region-contracts-regression/report.json`，124 项通过、零跳过。契约输出函数验证的参考是最终对象记录和最终网表，尚未建立从任意原始 RTL 到每个边界输出的完整语义证明。详见 [region-contracts.md](region-contracts.md)。

## 普通组合层次验收

`tests/test_hierarchy.py` 包含 16 项测试，使用原生和独立原版工具执行完整综合。默认保留层次，显式 `--flatten` 请求展平；实际产物分别和相同配置的原版完整 JSON modules 比较。用户的 keep_hierarchy 属性另有混合模式测试。

- 两层双实例中，同一行源码按 `demo/u0/inner` / `demo/u1/inner` 分别只选目标门；省略实例时返回两份。定义对象反查有歧义时不能默认选一个实例。
- 不同参数实例的宽度、数值参数及端口切片上下文正确；组合过程的动作报告保留实例身份。
- 不把共用模块定义当成共用物理门；展平后实际共享时必须保留两个输出的义务。
- 相同值的常量按具体实例端点区分；直连允许零 cell 导出。
- 两份实例契约可合并，重新验证全部输出并实际导出 Verilog；多门共同证明的闭合不能扩到兄弟实例。
- 保留层次的电气实例视图与原始设计另做完整等价检查；后续查询、契约验证不调用外部工具，重建视图必须与已验证产物相同。
