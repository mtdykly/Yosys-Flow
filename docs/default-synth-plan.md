# 目标：默认 synth 后按原始 RTL 位置导出子网表

用户已选择以 **Yosys 默认 `synth -top <top>`** 为下一阶段目标。当前已实现 opt_merge 末端的来源关联子网表导出；本文件描述后续开发设计，不代表完整 synth 已受支持。

## 最终交互与范围

用户提供 RTL、顶层和参数，按正常综合流程产生网表；随后指定原始源码文件、实例及语句/范围，得到：

1. 来源关联的最终 cell、连接和常量；存在删除事件时返回删除原因。
2. 可读取的 `.v` / `.il` 子模块，以及精确的外部输入/输出连接。
3. 共享来源、关联粒度、未覆盖步骤和实际综合终点。

“来源关联逻辑”与“完整扇入锥”使用不同选择策略。前者已经实现受限版本，后者可在边界索引上单独增加，不能混用来源图和电气连接图。

默认 synth 目标不等于某个 Liberty 标准单元库的映射。标准单元、LUT、`-flatten`、`-noabc` 等配置应作为后续独立 flow profile，不在没有记录的情况下混入默认目标。默认 synth 保留的模块层次也必须被追踪，不能为简化记录而偷偷改成全 flatten。

## 固定版本的阶段清单

以本仓库 Yosys `0e82bbefe` 的本机 `help synth` 为准，主要顺序如下。组合命令还会调用子 pass，表格不表示只插桩这些外层入口就能完整记录。

| 阶段 | 默认流程中的主要命令 | 需要的事件 |
| --- | --- | --- |
| 读取和层次 | `read_verilog`、`hierarchy -check` | AST/实例对象、参数派生、信号和单元生成 |
| coarse 开始 | `proc`、`opt_expr`、`opt_clean`、`opt -nodffe -nosdff` | process 到 mux/FF、常量替代、删除、合并、连接改写 |
| coarse 中段 | `fsm`、`opt`、`wreduce`、`peepopt`、`opt_clean` | 状态机提取/重编码、位宽变化、局部模式替换 |
| coarse 后段 | `alumacc`、`share`、`opt`、`memory -nomap`、`opt_clean` | 多算术对象合成、资源共享、memory 端口和状态转换 |
| fine 前段 | `opt -fast -full`、`memory_map`、`opt -full`、`techmap`、`opt -fast` | memory 展开、单元拆分、模板实例与位连接对应 |
| fine 后段 | `abc`、`opt -fast` | Yosys→ABC→Yosys 三段对应及映射后优化 |
| check | `hierarchy -check`、`stat`、`check` | 最终结构、层次和覆盖汇总 |

`opt`、`proc`、`memory`、`fsm` 都应展开核对内部实际调用。先通过小设计走过部分阶段，只能证明该设计触发的变换得到覆盖；不能据此标记任意 RTL 完整受支持。

## 建议实现顺序

**第一步：把记录器接到正常 Yosys 调用链。** 当前复制 pass 为 `trace_opt_merge` 适合验证方案；要让正常 `synth` 内部的原生 `opt_merge` 也被记录，应建立固定版本的 Yosys 源码补丁及构建方式，把事件钩子接回原实现。自定义命令只负责开关和导出记录。不要通过扩大 `src` 属性或添加 `keep` 改变优化决策。

将记录器拆成公共库接口，统一处理对象创建、版本变更、重命名、复制、删除和多对多替换。对内部句柄显式维护生命周期，避免地址重用/同名再创建继承旧身份。步骤增加父子关系，区分 synth/opt 包装步骤与实际变换步骤；同一事件只记录一次。框架入口能记录步骤开始/结束，语义来源事件仍须在实际转换位置主动记录。

**第二步：从组合 `always` 开始打通 proc 和基本 opt。** 先覆盖条件赋值生成 mux、简单寄存器生成 FF、常量化、删除和合并。需要保留连接/常量对应物及删除前的定义；当前“一个模块且无 process/FF”的限制只能在相应事件和测试落实后逐项放开。通过这一步才能把常见 RTL 接入，而不局限于连续赋值。

**第三步：推进到 techmap 前后，并处理层次。** 覆盖默认 coarse 中实际出现的 FSM、memory、算术、共享和位宽变换，随后接 memory_map 与 techmap。一对多 cell 拆分应带端口/位映射；实例对象应区分相同模块的不同使用上下文。宽泛的多对多关联可暂记为区域级证据，但查询必须报告粒度，不能宣称每个门都有精确来源。

**第四步：贯穿 ABC。** 每次调用使用独立 invocation_id，记录导出网络、ABC 内部改写/映射、重新导入三段。初期若只能确认一个区域的边界和成员，就只能返回该区域的候选结果，不能将边界对应当成任意内部门的精确来源。完整目标必须包括默认 ABC 及其后的 opt；关闭 ABC 只是开发阶段的检查点。

**并行的前端完善方向（开发顺序可交错）：** 新增独立语句/表达式 ID、源文件摘要、实例路径和列范围；在宏展开、generate、循环/函数展开、AST→RTLIL 中传递来源。现有列范围查询能减少误选，不能替代 AST 身份。原始源码中没有生成硬件的语句应返回“未生成/已消除/未知”及证据，而不是伪造一个对应门。参数条件依赖尤其服务于后续增量失效分析。

## 验收标准

- 普通 `synth` 与开启记录的相同流程在同一配置下功能一致；记录开关不改变优化约束。
- 每个已声明覆盖的步骤，其实际新增、删除和改接都能用事件解释；遗漏会使覆盖检查失败。
- 连续赋值、组合 always、寄存器 next-state、层次实例、宽运算拆门、FSM、memory、共享与常量删除各有真实综合案例。
- ABC 之后仍能由源码定位最终对象并反查；没有跨工具证据时明确返回缺口。
- 导出的子网表保留原最终 cell 的功能、参数与位连接；检查边界和共享使用，重新读取输出并验证导出格式等价。
- 查询坐标属于被记录的源码版本。后续编辑后的坐标转换另由差分层完成。
- 覆盖正确之后再测量全量快照、加载、建索引和查询成本；优先按运行缓存已验证索引、减少重复快照，JSONL 保留为事实记录，不因性能猜测提前换数据库。

当前 `extract` 已把最后一段查询/导出接口做成可复用模块。后续每补齐一个阶段的来源链，导出器便能对该阶段末端的 cell 继续工作；跨模块、时序边界和新对象类别仍需单独扩展，不能只更改报告里的阶段名称。
