# 从来源追踪扩展到增量综合

当前完成 opt_merge 的受控闭环，以及“源码位置 → 来源关联 cell → 带边界端口的子网表”。用户已确定后续以 Yosys 默认 `synth -top <top>` 为目标；具体阶段和验收见 [default-synth-plan.md](default-synth-plan.md)。以下完整来源与增量能力仍是待开发项。

1. **前端生命周期。** 在预处理、AST 简化和 AST→RTLIL 处记录源码对象、宏定义/使用、展开上下文、generate 分支选择和参数依赖；区分源对象与实例对象。为被折叠及未生成的对象保留定义和条件。测试“常量由 0 改 1，使旧逻辑重新出现”。
2. **proc 与其他优化。** 将当前统一记录器拆成可链接的公共实现，为创建、变更、重命名、删除增加生命周期接口。依次覆盖 proc、opt_expr、opt_clean、flatten、techmap。每种事件都要有重放不变量和实际快照对照。时序设计还需要状态对应，不能只把 FF 从当前拒绝列表中删除。
3. **实例与多对多区域。** 建立独立实例身份，记录参数派生、层次端口和 flatten 后的对象关系。粗粒度变换必须保存真实边界及成员，查询显式返回精度信息。不能将区域内任意对象当成安全切割点。
4. **ABC 交接。** 每次调用生成独立 invocation_id 和 `abc_0001.jsonl` 等文件；记录 Yosys 导出、ABC 内部转换和重新导入三段关系。可以先用 `abc -exe/-script/-nocleanup` 接入固定命令序列，但这些选项本身不会记录内部重写事件。
5. **RTL 差分与候选区域。** 使用 Base 坐标定位已有来源，结合 New 解析处理新增语句和条件失效。来源、共享使用和条件依赖分别扩张；遇到缺口或不确定状态边界则扩大范围或回退。
6. **局部重综合与证明。** 构造明确的输入、输出和状态边界，保留仍被外部共享的旧逻辑，综合局部实现并拼接；与 New 规范做等价验证。先用重复逻辑单侧修改、删除逻辑复活、寄存器下一状态修改三个案例检查。

在这些步骤完成前，当前查询仅提供候选区域的证据，不承诺安全复用。JSONL 保持事实记录；只有实验数据量或查询成本有实际需要时，再由 JSONL 生成 SQLite 索引。
