# 从旧记录与完整新版 RTL 自动推导局部替换

```bash
python3 -m incremental auto \
  --base-run runs/old-run \
  --new-source path/to/new.v \
  --out runs/automatic-edit
```

输入是旧综合运行目录和完整新版 RTL；多个源文件重复 `--new-source`。不需要提供修改行号、实例、局部代码、契约或绑定。`--out` 必须是新目录。工具链路径可通过 `--yosys`、`--native-yosys` 指定。

旧记录必须包含校验通过的 `frontend.il`、最终网表、来源及 ABC 证据。源码文件可以已被修改或删除。顶层名、顶层参数、宏、include 目录和是否 flatten 继承旧 manifest；新版需能在这些编译条件下展开，新增 include 文件仍需可访问。本轮不提供编译配置迁移，要求顶层端口名、方向、位宽及位序保持不变。

## 推导过程

1. **读取旧表示。** 重放、校验旧记录，读取当时保存的 `proc` 前 `frontend.il`，不重新读入或综合旧源码。
2. **展开完整新版。** 用原生前端及 `hierarchy` 展开新版，保留完整过程体、端口、参数和实例关系。另运行 `proc; check` 检查组合逻辑范围、计算端口依赖；这里没有运行 `synth`、`techmap` 或 ABC。保存全部源文件/include 的哈希。
3. **寻找模块内修改种子。** 先按实际实例路径比较模块本体。对单模块或叶模块，继续比较 `proc` 前具名赋值目标各位的定义：追踪前端临时表达式、过程动作顺序、包围条件以及先前 `case` 分支的优先级。源坐标、生成名称变化本身不算修改。其他具名信号是此层比较的叶子，因此仅修改 `t=a&b` 不会把未改写的 `y=t^c` 也列为源码修改种子。
4. **生成旧区域契约。** 用旧表达式的源码范围或过程动作的赋值身份查询旧来源，以 `source_cells` 派生所关联的实际门集合，补齐已记录共同门组。保留所有实际门的外部输出和消费者；不把内部常量填充等源码观察连接作为门替换的额外输出。每个修改种子必须有门关联，否则进入模块后备方案。仍要求 `verified_old_region`；不提升候选来源精度。
5. **提取新版完整局部功能。** 将旧契约的实际输出信号对应到新前端中的具名功能锚点，再从新版 `proc` 后粗粒度表示向输入遍历，只复制必要单元。Yosys 已保留 `if/case`、默认赋值和覆盖优先级；不会按文本剪一行，也不会因同一 `always` 含另一个独立目标就复制整个过程。粗粒度向量单元整颗复制，可能保守多选部分位。
6. **证明可复用输入并确定绑定。** 旧电气身份必须来自已验证实例视图、端口绑定或真实 flatten 复制关系。新旧具名锚点的完整前端依赖指纹也必须相同，才允许它作为复用输入切点；这一层会穿过其他具名信号，防止把已受上游修改影响的中间值误当成不变输入。新版额外使用的旧外部信号生成 `extend_inputs` 并重验全部旧输出。旧共享信号在新版对应不同函数时拒绝该切片。已记录的常量实例输入只按实际端口绑定连接，不能按常量值猜身份。
7. **逐步扩区与后备。** 无法找到某个旧输出的新功能锚点时，纳入实际外部消费者，重新切边界和验证契约，最多尝试 32 次。局部接口变化、含子实例的父模块修改、不支持的表示、来源不足或无法闭合的输出，转用原来的整模块及父实例策略，最多 65 次。该后备从新版 `proc` 前表示复制完整模块及子模块；仅对已证明没有输出依赖的未绑定输入接 0。顶层仍不满足条件就报告阻塞。
8. **局部综合、拼接、验收。** 只综合提取的 `patch.il`，验证所有边界输出、外部消费者、单驱动、无环及未选门不变。候选生成后，才完整综合冻结的新版前端表示作为参考，验证全部顶层输出和交付 Verilog 重读等价。最后复核旧归档及新版输入哈希，发布网表。

规范化差分是结构比较，不是功能等价证明。条件等价改写可以被判为修改，独立语句重排也可能产生保守扩区；最终全输出 SAT 验收始终保留。若没有结构变化，则直接复用全部旧门，仍验证完整新版与输出 Verilog。

## 粒度与限制

默认粒度是**变化赋值或表达式所在的目标位及其必要语义、旧来源门组和边界闭包**。它可以明显小于单个模块；不保证一条语句或一个表达式恰好对应一个门，也不保证最小切片。改变同一共享定义会处理所有受影响实例。父模块接线、实例增删等变化仍使用模块策略。

结构指纹是保守比较，不等价于局部功能证明：等价表达式重写也可能扩区。只有最终局部绑定、契约和全部输出 SAT 都通过才能发布。计划阶段失败会尝试模块后备；候选进入最终验证后若 SAT 失败，当前直接拒绝，不自动枚举更大的选区直到通过。

支持范围继承组合来源前端：普通组合层次、连续赋值及已支持的组合过程；时序、锁存、memory、generate、循环、函数/任务仍拒绝。参数派生模块保留真实 `$paramod` 身份。保留层次或显式 flatten 的旧记录都可输入，但展平后的 ABC 证据缺口仍可能阻塞；交付网表是展平的通用门网表。

当前不自动拆分同一旧信号的不同消费者，不保证能处理新直连/常量变门、端口身份消失、任意模块接口变化或任意共享改写。扩大到顶层也不能消除候选来源或连接义务。部分情况最终报告验证失败，均不发布网表。失败是当前策略或证据的限制，不说明这项 RTL 编辑无法通过其他方式实现。

验证只适用于本次完整新版及实际绑定，继续保留旧契约的 `safe_for_incremental_reuse=false` 和来源缺口声明。没有生成替换后设计的完整连续来源日志。

## 产物与验收

| 路径 | 内容 |
| --- | --- |
| `difference.json` | 实例、旧/新模块及源码范围、规范表示差异和指纹 |
| `statement-plan.json` | 修改目标位、旧/新定义指纹、源码选择器、消费者扩区步骤或模块后备原因 |
| `region.contract.json` | 自动选择、并集或增加输入后的可重放契约 |
| `patch.il` / `patch.v` | 只包含局部功能及包装；Verilog 是便于检查的转换结果 |
| `bindings.json` | 全部边界输入输出的自动连接 |
| `patch-specification.json` | 策略、实际端点证据、具名锚点的完整定义指纹、新增输入、复制的局部单元及数量；模块后备另列未使用输入 |
| `work/new.frontend.il` / `new.coarse.json` | 完整新版展开结果及组合检查表示 |
| `work/statement-slice.json` / `.il` | 从新版粗粒度表示提取的局部功能，只在语句切片成功时生成 |
| `replacement/` | 局部综合、拼接、独立边界检查、完整新版参考及全部验证脚本/日志 |
| `incremental.v` / `incremental.json` | 全部检查通过后才交付的网表 |
| `report.json` | 状态、扩区尝试、门数、哈希、逐阶段耗时及失败原因 |

`status=unchanged` 时不生成 patch，保存复用和等价验证结果。`blocked` 或 `failed` 的 `auto` 命令非零退出。`incremental_candidate_ready_seconds` 包含旧记录重放、新版前端和组合检查、差分、契约生成验证、绑定、局部综合与拼接；完整新版参考综合和验收单独记录，没有时间加速承诺。

用 ANUBIS 复现自动模式：

```bash
python3 -m incremental anubis --automatic \
  --cases compare_local9 --mode retained --out runs/automatic-anubis
```

基准准备器只负责生成完整版本并综合旧版，随后仅把旧运行目录和新版文件交给自动算法；不提供预设目标实例、源码行号或局部规范。`compare_local9` 自动发现 `benchmark/u_target` 内的 `Result` 修改，从旧 231 个门中替换 110 个、复用 121 个；此前整叶模块策略为替换 115 个、复用 116 个。`bypass_noc1` 从替换 31 个细化到替换 29 个，63 个旧门中复用 34 个。均须通过全部输出验证，门数减少不代表已获得时间加速。

`incremental/tests/test_automatic.py` 还覆盖格式/模块名变化时全部复用、共用定义修改自动选择两个实例、参数派生、新增输入依赖、旧源码删除、归档篡改、候选不得升级、契约输入扩展导出及合并内部化。

`incremental/tests/test_statements.py` 使用固定 ANUBIS 的表达式及明确声明的过程、位宽、连接适配，增加以下验收。这些小例子不是未经修改的完整上游模块，也不加入上游宏测试的成功数。

| 案例 | 验收 |
| --- | --- |
| 4 位 AND→XOR，旁边独立 OR | XOR 改 OR，只替换 4/12 个门；上游 AND 和独立 OR 的 8 个门及连接不变 |
| 同一 `always` 的条件数据选择与独立 OR | 分别以 `if`、`case` 表达，改变分支操作数；只替换 4/8 个门，保留条件与独立目标，新输入自动绑定 |
| 新表达式使用原来的 `side` | 验证其完整依赖未变，新增该实际旧信号作为输入，保留驱动它的门 |
| 注入内部 `t` 身份不可用 | 不改旧归档，仅让端点解析器返回缺失；沿真实下游扩区，替换 8/12 个门，记录原因并通过全部输出 SAT |
| 比较器与嵌套条件 | 修改种子只涉及目标；旧 ABC 来源仍为候选时报告阻塞，不能借全输出验证升级 |
| 原始 `ANUBIS_LOCAL_3` 常量修改 | 原宏 `r31` 是 6 位而所比字段为 5 位，旧函数实际为常量；要求消费者重绑定，当前拒绝 |
| 契约篡改 | `source_cells` 从旧记录重放验证，删门、删外部使用者并重新封装哈希仍拒绝 |

指纹单元测试另检查先前 `case` 优先级、动作次序和上游修改对可复用切点的影响。完整回归将 `automatic/`、`statements/` 的输入、脚本和产物保存在报告目录；仍要求零跳过。
