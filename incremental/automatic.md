# 从旧记录与完整新版 RTL 自动推导局部替换

```bash
python3 -m incremental auto \
  --base-run runs/old-run \
  --new-source path/to/new.v \
  --out runs/automatic-edit
```

输入是旧综合运行目录和完整新版 RTL；多个源文件重复 `--new-source`。不需要提供修改行号、实例、局部代码、契约或绑定。`--out` 必须是新目录。工具链路径可通过 `--yosys`、`--native-yosys` 指定。

旧记录必须包含校验通过的 `frontend.il`、最终网表、来源及 ABC 证据。新建归档保存 `verified-index.sqlite3`，在线按需读取已验证的重放/来源状态；旧归档缺少索引时仍可重放，不要求重新综合，旧 gzip 索引保留兼容读取。源码文件可以已被修改或删除。顶层名、顶层参数、宏、include 目录和是否 flatten 继承旧 manifest；新版需能在这些编译条件下展开，新增 include 文件仍需可访问。本轮不提供编译配置迁移，要求顶层端口名、方向、位宽及位序保持不变。

## 首次建档与在线替换计划

首次插桩全量综合的事件仍是来源主体。归档中的 `verified-index.sqlite3` 保存验证后的来源状态，以及源码到最终对象、正反向转换边、门组最终成员、驱动者、消费者及别名索引。它绑定原始产物与实现版本，仅作本地验证加速副本，不是独立来源证据，也不会把候选升级为精确来源。每次仍核对原始产物哈希；索引校验和读取属于在线成本，索引创建属于一次性建档成本。ABC 检查点/差量和按需读取的具体范围见[存储说明](../provenance/docs/storage.md)。

索引通过本机 `build/.verified-index-auth-key` 认证，密钥不进入归档或 Git。没有索引、实现不兼容、归档复制到无密钥或不同密钥的环境时，工具从原始记录完整重放；不会自动改写旧归档。内容损坏拒绝，重新封装普通内容哈希不能跳过本地认证。原始日志继续保留，`python3 -m yosys_flow validate <旧归档目录>` 强制完整重放；内部接口也可设置 `load_run(..., use_index=False)`。

新版到来后才能知道本次需要哪些区域、额外输入和消费者绑定，因此不预先枚举所有可能契约。自动流程使用 v2 `replacement_plan`，保留选区、边界、旧输出验证及共享义务，证据通过旧对象/事件引用取得。它避免递归嵌入父契约和反复复制相同来源，但不省略实际选区与绑定分析。

`replacement-plan.json` 是本次计划的唯一主文件；替换报告的 `selection_document` 记录其路径和哈希，不再另写同内容的 `contract.json`。`bindings.json` 继续以 `contract_id` 字段绑定计划内容，兼容显式接口。需要完整来源说明时，仍可独立使用 `yosys_flow contract` / `contract-validate` / `contract-merge`，默认生成完整 v1 契约；这些工具不在自动路径中重复执行。

## 功能不变时直接复用

自动流程默认先尝试固定 Yosys 的 `miter + sat`，不新增 EQY 依赖。只比较**接口一致、实例上下文未变的变化叶模块**，匹配全部输入和全部输出；同一新旧模块定义对在多个实例中只证明一次。不按内部同名信号加等价假设。

证明输入来自旧归档与新版 `proc` 前表示，经 `proc; opt_expr; opt_clean` 转成组合表示，未执行 `synth`、`techmap` 或 ABC。miter 比较全部模块输出；SAT 对所有二值输入证明差异 `trigger=0`，同时证明两边输出始终有定义。后一个义务防止普通 `eqx` 把“两边都为 X”当成可以直接复用的证据；不启用忽略未知单元、忽略除零或 `ignore_gold_x`。

| 结果 | 行为 |
| --- | --- |
| `equivalent` | 从初始待处理实例中排除；叶模块全部输出等价且有定义 |
| `different` | 保存二值反例，继续原来的变化赋值、局部提取与替换 |
| `unknown` | 超时、预算耗尽、不支持、输出未定义或缺少成功证据；继续原流程，不能当作等价或不等价 |

如果全部修改都已证明等价，还要检查未变上下文能够提供二值输入：已证明的叶定义可直接使用，其他模块只接受已知为全定义的组合单元和二值连接。X/Z 连接、未认证的三态、除法等上下文保守回退，不能只假定叶输入一定满足证明前提。父模块接线、模块接口或实例结构变化不进入这条叶模块捷径。

通过后 `status=reused_equivalent`，直接逐字节复制旧 `after.json`、`after.v`，保留原层次；不生成 patch，不做局部综合或拼接，也不再次全量综合新版。证明依据是已验证的旧综合结果、未变的结构上下文，以及覆盖所有修改的叶模块证明。结构完全相同则 `status=unchanged`，同样直接复用。两条路径都在发布前复核旧归档、新版源文件与表示、证明脚本和产物的哈希。

只有部分修改等价时，其余部分继续局部综合，交付前仍做原来的完整新版全输出 SAT 和 Verilog 重读验收。必要的扩区可能重新纳入最初排除的实例，因此不保证每个等价实例的门都一定保留。

```bash
# 默认开启：每个证明最多 5 秒，总证明预算 15 秒
python3 -m incremental auto --base-run runs/old-run --new-source new.v \
  --out runs/edit-with-precheck

# 限制预算；包含证明所需的表示转换、SAT 导入和求解
python3 -m incremental auto --base-run runs/old-run --new-source new.v \
  --equivalence-timeout 2 --equivalence-budget 6 --out runs/edit-short-budget

# 对照原有局部综合路径，或希望等价改写仍有机会改善 PPA
python3 -m incremental auto --base-run runs/old-run --new-source new.v \
  --no-equivalence-precheck --out runs/edit-without-precheck
```

`anubis --automatic` 接受相同三个选项。预算包含预处理/导入的进程墙钟时间，另给 SAT 求解器设置超时；所有实例共享总预算，缓存证明不重复求解。目标是减少功能保持型修改的综合工作，**不保留等价重写可能带来的面积或时序优化收益**。

## 推导过程

1. **读取旧表示与索引。** 核对归档和索引身份，加载首次建档保存的来源状态；缺少兼容索引时重放旧记录。读取保存的 `proc` 前 `frontend.il`，不重新读入或综合旧源码。
2. **展开完整新版。** 用原生前端及 `hierarchy` 展开新版，保留完整过程体、端口、参数和实例关系。另运行 `proc; check` 检查组合逻辑范围、计算端口依赖；这里没有运行 `synth`、`techmap` 或 ABC。保存全部源文件/include 的哈希。
3. **等价预检查与修改种子。** 先按实际实例路径比较模块本体，执行上述有预算的叶模块等价检查。对剩余单模块或叶模块，继续比较 `proc` 前具名赋值目标各位的定义：追踪前端临时表达式、过程动作顺序、包围条件以及先前 `case` 分支的优先级。源坐标、生成名称变化本身不算修改。其他具名信号是此层比较的叶子，因此仅修改 `t=a&b` 不会把未改写的 `y=t^c` 也列为源码修改种子。
4. **确定旧区域并生成轻量计划。** 用旧表达式的源码范围或过程动作的赋值身份查询旧来源，以 `source_cells` 派生所关联的实际门集合，补齐已记录共同门组。保留所有实际门的外部输出和消费者；不把内部常量填充等源码观察连接作为门替换的额外输出。每个修改种子必须有门关联，否则进入模块后备方案。仍要求 `verified_old_region`；不提升候选来源精度。
5. **提取新版完整局部功能。** 将旧区域的实际输出信号对应到新前端中的具名功能锚点，再从新版 `proc` 后粗粒度表示向输入遍历，只复制必要单元。Yosys 已保留 `if/case`、默认赋值和覆盖优先级；不会按文本剪一行，也不会因同一 `always` 含另一个独立目标就复制整个过程。粗粒度向量单元整颗复制，可能保守多选部分位。
6. **核对可复用输入并确定绑定。** 旧电气身份必须来自已验证实例视图、端口绑定或真实 flatten 复制关系。新旧具名锚点的完整前端依赖指纹也必须相同，才允许它作为复用输入切点；这一层会穿过其他具名信号，防止把已受上游修改影响的中间值误当成不变输入。新版额外使用的旧外部信号生成 `extend_inputs` 并重验全部旧输出。旧共享信号在新版对应不同函数时拒绝该切片。已记录的常量实例输入只按实际端口绑定连接，不能按常量值猜身份。
7. **逐步扩区与后备。** 无法找到某个旧输出的新功能锚点时，纳入实际外部消费者，重新计算边界并验证计划，最多尝试 32 次。局部接口变化、含子实例的父模块修改、不支持的表示、来源不足或无法闭合的输出，转用原来的整模块及父实例策略，最多 65 次。该后备从新版 `proc` 前表示复制完整模块及子模块；仅对已证明没有输出依赖的未绑定输入接 0。顶层仍不满足条件就报告阻塞。
8. **局部综合、拼接、验收。** 只综合提取的 `patch.il`，验证所有边界输出、外部消费者、单驱动、无环及未选门不变。候选生成后，才完整综合冻结的新版前端表示作为参考，验证全部顶层输出和交付 Verilog 重读等价。最后复核旧归档及新版输入哈希，发布网表。

规范化差分是结构比较，不是功能等价证明。SAT 未能证明的等价改写仍可能被当作修改，独立语句重排也可能产生保守扩区。实际执行局部替换的路径始终保留最终全输出 SAT 验收；整份旧网表直接复用的路径使用前述组合证明，不执行新版完整综合。

## 粒度与限制

默认粒度是**变化赋值或表达式所在的目标位及其必要语义、旧来源门组和边界闭包**。它可以明显小于单个模块；不保证一条语句或一个表达式恰好对应一个门，也不保证最小切片。改变同一共享定义会处理所有受影响实例。父模块接线、实例增删等变化仍使用模块策略。

结构指纹是保守比较，不等价于局部功能证明。需要实际替换时，只有局部绑定、旧区域计划和全部输出 SAT 都通过才能发布。计划阶段失败会尝试模块后备；候选进入最终验证后若 SAT 失败，当前直接拒绝，不自动枚举更大的选区直到通过。

支持范围继承组合来源前端：普通组合层次、连续赋值及已支持的组合过程；时序、锁存、memory、generate、循环、函数/任务仍拒绝。参数派生模块保留真实 `$paramod` 身份。保留层次或显式 flatten 的旧记录都可输入。需要局部替换时，ABC 证据缺口仍可能阻塞，交付为展平网表；直接复用整份旧网表则保留其原有层次形态，无需从 ABC 候选中选门。

当前不自动拆分同一旧信号的不同消费者，不保证能处理新直连/常量变门、端口身份消失、任意模块接口变化或任意共享改写。扩大到顶层也不能消除候选来源或连接义务。部分情况最终报告验证失败，均不发布网表。失败是当前策略或证据的限制，不说明这项 RTL 编辑无法通过其他方式实现。

验证只适用于本次完整新版及实际绑定，继续保留旧区域的 `safe_for_incremental_reuse=false` 和来源缺口声明。等价复用也不重写旧源码坐标、AST 身份或 ABC 因果历史；交付目录不是可直接作为下一轮 `--base-run` 的新来源归档。

## 产物与验收

| 路径 | 内容 |
| --- | --- |
| `difference.json` | 实例、旧/新模块及源码范围、规范表示差异和指纹 |
| `equivalence-precheck.json` | 开关、预算、逐实例证明结果、缓存命中、未处理实例与直接复用的上下文检查 |
| `work/equivalence/proof-N/` | 新旧局部表示、全部输出 miter、定义性检查、SAT 脚本/日志和反例 WaveJSON |
| `statement-plan.json` | 修改目标位、旧/新定义指纹、源码选择器、消费者扩区步骤或模块后备原因 |
| `replacement-plan.json` | v2 轻量替换计划：旧区域、边界、使用义务、验证结果和归档证据引用；不嵌套整份父契约 |
| `patch.il` / `patch.v` | 只包含局部功能及包装；Verilog 是便于检查的转换结果 |
| `bindings.json` | 全部边界输入输出的自动连接 |
| `patch-specification.json` | 策略、实际端点证据、具名锚点的完整定义指纹、新增输入、复制的局部单元及数量；模块后备另列未使用输入 |
| `work/new.frontend.il` / `new.coarse.json` | 完整新版展开结果及组合检查表示 |
| `work/statement-slice.json` / `.il` | 从新版粗粒度表示提取的局部功能，只在语句切片成功时生成 |
| `replacement/` | 局部综合、拼接、独立边界检查、完整新版参考及全部验证脚本/日志 |
| `incremental.v` / `incremental.json` | 全部检查通过后才交付的网表 |
| `report.json` | 状态、扩区尝试、门数、哈希、逐阶段耗时及失败原因 |

`status=unchanged` 或 `reused_equivalent` 时不生成 patch，报告 `reuse`、证明依据和逐字节复用检查。实际替换成功仍为 `passed`；`blocked` 或 `failed` 非零退出。`changes` 保留原始差异，`remaining_changes` 是预检查后待处理差异。替换路径的 `netlist_generation_seconds` 截止于完整新版 JSON/IL/Verilog 写出，包含旧索引加载或记录重放、新版前端、预检查、差分、选区、计划、绑定、局部综合与拼接；生成后的检查单列为 `post_generation_validation_seconds`。历史 `incremental_candidate_ready_seconds` 仍含部分检查，仅用于诊断，详见 [计时定义](comparison.md#时间到整份新版网表生成)。直接复用路径用 `timings.total_seconds` 观察完整在线成本，不能把 SAT 求解耗时当作总耗时。

用 ANUBIS 复现自动模式：

```bash
python3 -m incremental anubis --automatic \
  --cases compare_local9 --mode retained --out runs/automatic-anubis
```

基准准备器只负责生成完整版本并综合旧版，随后仅把旧运行目录和新版文件交给自动算法；不提供预设目标实例、源码行号或局部规范。`compare_local9` 先找到功能差异反例，再自动选择 `Result` 修改，从旧 231 个门中替换 110 个、复用 121 个。`bypass_noc1`、`compare_noc2` 默认直接复用全部旧门；关闭预检查时仍验证原局部路径（旁路为替换 29/63 个门，比较器为旧来源选区）。

`incremental/tests/test_equivalence.py` 用这些 ANUBIS 宏修改验证：全部输出、未定义输出不可证明、超时/预算耗尽回到原流程、混合功能修改只过滤等价实例、共用定义证明缓存、父接线变化不跳过、保留层次与展平的原网表逐字节复用、证据篡改拒绝。测试另在自动流程之外做完整新版综合及全输出等价对照，不能把该测试参考误算为直接复用路径的综合工作。`equivalence/comparison.json` 保存开关各一次的总耗时、状态与详细报告，属于同机样本，不能推广到任意规模或修改。

`incremental/tests/test_automatic.py` 还覆盖格式/模块名变化时全部复用、共用定义修改自动选择两个实例、参数派生、新增输入依赖、旧源码删除、归档篡改、候选不得升级、契约输入扩展导出及合并内部化。

`incremental/tests/test_statements.py` 使用固定 ANUBIS 的表达式及明确声明的过程、位宽、连接适配，增加以下验收。这些小例子不是未经修改的完整上游模块，也不加入上游宏测试的成功数。

| 案例 | 验收 |
| --- | --- |
| 4 位 AND→XOR，旁边独立 OR | XOR 改 OR，只替换 4/12 个门；上游 AND 和独立 OR 的 8 个门及连接不变 |
| 同一 `always` 的条件数据选择与独立 OR | 分别以 `if`、`case` 表达，改变分支操作数；只替换 4/8 个门，保留条件与独立目标，新输入自动绑定 |
| 新表达式使用原来的 `side` | 验证其完整依赖未变，新增该实际旧信号作为输入，保留驱动它的门 |
| 注入内部 `t` 身份不可用 | 不改旧归档，仅让端点解析器返回缺失；沿真实下游扩区，替换 8/12 个门，记录原因并通过全部输出 SAT |
| 比较器与嵌套条件 | 修改种子只涉及目标；旧 ABC 来源仍为候选时报告阻塞，不能借全输出验证升级 |
| 原始 `ANUBIS_LOCAL_3` 常量修改 | 原宏 `r31` 是 6 位而所比字段为 5 位，旧函数实际为常量；要求消费者重绑定，当前拒绝 |
| 契约篡改 | `source_cells` 从旧记录重放验证，删门、删外部使用者并重新封装哈希仍拒绝 |

指纹单元测试另检查先前 `case` 优先级、动作次序和上游修改对可复用切点的影响。完整回归将 `automatic/`、`statements/`、`equivalence/` 的输入、脚本和产物保存在报告目录；仍要求零跳过。原有自动局部提取专项明确关闭预检查，防止等价捷径替代对原路径的回归覆盖。
