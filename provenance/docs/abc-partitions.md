# 目标窗口、功能边界与新归档

`tools/refine_partitions.py` 从已认证的旧归档补充功能对应证据。它不读取新版 RTL，不执行设计的 `synth`，不覆盖旧归档。入口要求 SQLite；目前发布范围为单模块组合逻辑。

处理顺序：

1. 根据指定的 ABC 输入 cell，沿实际连接找受影响的捕获输出。只证明这些输出所需的依赖；其他输出在报告中明确列为跳过。窗口失败分别报告入口侧/导出侧、节点数、边界数和待扩展分支。
2. 结构相同的函数可直接作为边界。仿真只提出可能对应的信号；对应必须由独立边界上的 BDD/SAT，或经过验证的原始 ABC 成功求解事件支持，才能保存根节点、极性和证明依据。
3. 条件证明按依赖顺序处理。尚未证明的对应不能成为有效假设，循环依赖不予接受。局部窗口或求解预算不足时，允许对具体阻塞边界使用 ABC CEC，在全部捕获 PI 上证明函数对应；这一步单独计时并限制次数。启用 `--checkpoint-bridges` 后，从原始 ABC 日志恢复实际命令检查点，逐段验证同一函数及极性；必要时先补充该段内部的小边界。检查点中的相同节点编号或仿真签名都不能直接作为证明。CEC 与检查点分段证明不意味着完整的 ABC 因果历史。
4. 从已证明边界重新划分区域。检查所有对外输出及共享使用者，在独立切割输入上证明区域函数；随后从归档 `frontend.il` 重建旧功能，执行全部对外输出的来源证明。全部通过才在新目录复制原归档、补充 SQLite 表，并重新绑定产物摘要和签名。

`functional-partitions.json` 保存函数边界、区域、全部输出、来源证明和分段证据。SQLite 的 `functional_partitions` 表保存可直接查询的证书。原始对象、原始候选来源和原始转换边保留；新证书为自动增量流程提供有依据的修改影响区域，不把原来的候选记录改称完整因果关系。

检查点路径还复用固定 ABC 钩子捕获的 `dch_sat_merge` 和 `dch_structural_merge`。前者只位于 `Dch_NodesAreEquiv` 返回“已证明等价”的分支，后者位于经过已有等价合并后两个结构根相同的分支。读取已认证捕获并核对快照后，将这些结果作为全称布尔等式，经显式变量重命名和 AND/反相表达式的同余传播使用。记录事件编号、快照、极性和依赖；不会把普通 `aig_replace` 或候选签名当作等价证明。这是复用受信任求解器的历史成功结果，并非重新执行 SAT 或检查 DRAT；全部对外输出的旧 RTL 独立切割证明仍然必须通过。

`--recorded-rewrites` 进一步重放实际 `aig_replace` 事件。每次从事件绑定的不可变快照取旧根、新根和极性，在相同的独立切割输入上进行真值表或 BDD 证明，只有通过的等式才参与后续同余传播。共同切点可能相互依赖，例如同时切到 `t` 和 `t & u`；初始独立切割不能证明时，程序展开切点再试，不直接假设两者的关联。共同边界搜索最多 64 层、4096 个节点；实际局部证明仍限制为 256 个节点和 64 个独立输入，两者分开控制。局部 BDD 预算耗尽时，用同一独立切割问题尝试至多 1 秒的 SAT；超时保留未知。节点身份限定在网络 epoch 内，删除、复用 ID 和连接变化都会更新函数缓存。无法证明的替换保持未知。补充证据保存为 `abc-rewrite-lemmas.json.gz` 并绑定新归档摘要，不修改原始日志。

自动流程仍比较完整新旧 RTL，检查边界输入的新版功能是否保持不变，生成 patch，验证绑定和最终网表。新证书不是对任意修改的预先授权。已归档的旧区域证明只有在前端摘要、选中对象、全部边界和函数一致时才可复用。

对实际 `dch_choice_copy`，复制前后的节点使用分开的身份空间。程序先核对已成功的 DCH 合并事实确实属于复制源快照，再按拓扑顺序验证每条实际复制关系及极性；只有已验证的复制可作为后续节点的边界。源、目标编号相同不能替代证明，未通过的复制和输出单独保留。相应的快照、输入绑定和逐项结果写入补充证据。

实际映射 cut 另由 `abc_mapping.py` 检查。先核对 GIA、映射后 NTK 和导出网表之间的实际绑定，再把每个选中门的输入换回同一 GIA 快照中的叶节点，独立证明“原根函数及极性 = 该门作用于这些叶节点”。choice 的叶节点未必支配原根，因此共同边界从两侧祖先中寻找；不会仅凭 cut 被选中就接受它。通过的等式可沿映射网表传播，避免反复证明庞大的全 PI 扇入锥；未通过的 cut 留在未知清单。`mapping-lemmas.blif` 和 `mapping-lemmas.json` 一并绑定新归档。

小窗口未证明的映射 cut，最多额外选择 8 个，在同一源 GIA 的全部独立 PI 上尝试 CEC；时间沿用 `--cec-timeout`。两侧保留相同的上游结构，因此与直接比较整个前后映射网络的成本不同。只有明确的等价成功结果才能加入等式；超时、工具不可用或不等价仍留在未知清单。

映射证明导出时保留门本身的真值表和实际输入极性，GIA 叶节点的反相使用显式共享反相节点表达。把所有反相直接折入真值表虽然功能正确，却会隐藏相同门函数的应用，妨碍已经证明的关系沿网表传播。这项表示修正不增加等价假设。

函数传播同时保留实际表达式与规范化表达式，并记录由已证明操作数相等推出的同余等式。AND 结合律、幂等律及反相规则用于识别重新平衡后的同一函数，交替检查原始形状和已证明代表元的形状；只看其中一种会遗漏由重构隐藏的边界。规范化有规模、工作量和轮数上限，超限只会减少可识别的等式。这样可以从原始捕获重新构造边界证据，不依赖诊断进程中偶然保留的内存状态。

```bash
python3 -u provenance/tools/refine_partitions.py OLD_ARCHIVE \
  --input-cell CAPTURED_ABC_INPUT_REF \
  --out NEW_DIAGNOSTIC_DIRECTORY \
  --sat-timeout 60 --cec-timeout 60 --cec-attempts 32 \
  --checkpoint-bridges --recorded-rewrites \
  --publish NEW_ARCHIVE_DIRECTORY
```

`--node-limits` 限制窗口大小；`--sat-timeout` 限制每个局部求解；`--local-backend abc_cec` 可改用 ABC CEC 证明独立边界上的局部 miter；`--cec-timeout` 限制一次捕获 PI 边界证明，`--cec-attempts` 限制每个证明器的尝试次数。检查点各段使用独立证明器，这不是整个离线任务的总时间预算。超时或证据不足均保持未知。`--reuse-pairs pairs.json` 会重新证明缓存中的普通对应，不能仅靠 JSON 中的成功标志升级结果。含检查点链的证明目前需从原始检查点重做，不能作为只含端点的缓存导入。

已证明的反相边界以 `inverted` 保存。旧来源证明和新版 patch 提取都显式处理该极性，不能把反相信号直接当成同名的原始 RTL 信号。这个独立细化命令只读取旧记录，可以事先生成可复用证书。计时应按实际触发条件划分：若由本次新版差分触发补证，补证也是在线准备成本；只有事先生成或已经缓存的证书，才能在后续测量中单列为离线成本。针对已知 ECO 预先补证后的在线时间属于证书命中的热路径，不代表任意未知修改的冷启动收益。

最终网表可能同时使用一个信号及其反相。如果两者同时出现在候选输入边界，不能把它们当作两个自由输入后直接假设互补，也不能合并两个电气驱动。选区保留拓扑上较早的驱动作为输入，将下游反相门纳入区域，并验证该门的全部对外输出和使用者。因此，同一个原始信号可以对应一个反相输入边界以及一个需保留的同相输出；来源证明和 patch 提取均保留这两个实际连接。源侧为计算局部功能而复制的未变化辅助逻辑，不单独产生修改义务；所有受修改影响的源侧外部输出和所有最终区域外部输出仍需覆盖。

诊断目录的 `report.json` 只有在区域和来源证明全部通过后才为 `verified`；真正发布成功还应有 `published_index_verified=true`。目录中出现 `pairs.json` 或部分成功证明，不表示该目标已经可以增量替换。发布目录必须不存在；若补充另一组目标，应从原始捕获重新派生，暂不支持嵌套发布。

新归档同时保存所引用的命令检查点、DCH 成功事件、复制证明和局部改写等式，并全部纳入摘要与签名。后续查询不需要保留临时诊断目录。原始日志仍保留，来源候选和已证明的区域证据分别表达。

检查点诊断中的 `structural=true` 表示在当时已安装的证明等式下，两端已属于同一函数类，可能依赖前面的 SAT 或复制证明；它不单独声称两份原始网表逐门结构相同。具体依赖保存在该阶段的 `proofs` 中。

小例子验收覆盖：候选误匹配与极性错误拒绝、循环检测、窗口侧别、条件依赖、全部对外输出、独立输出排除、新归档读取、旧归档保持不变、完整增量及损坏证据拒绝。大案例结果单独记录，不由小例子推断。
