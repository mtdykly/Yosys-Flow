# 耗时归因与针对性优化

本轮只处理单模块组合逻辑下的耗时归因和已测瓶颈；没有扩大 RTL 支持范围，也没有实现寄存器边界。继续使用已冻结的 EPFL `adder_local`、`adder_shared` 修改，并诊断 `arbiter` 旧建档。

后续将归因扩展到全部既有 ANUBIS/EPFL 适配案例的结果见 [多案例耗时归因](cost-attribution-suite.md)。本文保留当时的优化前后测量，不用后续样本覆盖历史数据。

## 测量口径

- `adder` 源码 1,205 行，旧网表 764 门；`arbiter` 源码 13,189 行。选取的修改、顶层、默认 `synth` 和工具版本沿用上一轮。P-fine 使用默认 SQLite、保留层次模式、关闭等价预检查。
- 在线时间截至完整新网表 JSON/RTLIL/Verilog 写出，包含选区所需证据检查；首次旧建档、离线重建索引、生成后的全输出等价与交付检查不计入生成时间。
- 诊断使用函数级嵌套墙钟计时和每 20 ms 一次的 Python CPU 采样。独占时间可相加，包含子调用的时间不可相加。CPU 栈采样只定位 Python 热点，不当作 Yosys/ABC 或墙钟占比。
- 前后各一次诊断；优化后另用未启用诊断的进程分别执行一次 F 和 P-fine。在线测量在回归及离线任务结束后，固定 CPU 2 串行运行；没有清空操作系统缓存，也没有计算统计均值。建档诊断同时有 CPU 4 上的回归，绝对时间存在同机负载影响。
- 诊断适配器为新增函数和建档子进程补充了细分跨度，因此不将诊断样本当成无测量开销的严格加速比。未启用诊断的生成时间单列。
- 空快照读取器变化会使旧索引的实现指纹失效。后测在旧 adder 归档副本中重新重放验证并构建索引，所有原始证据逐文件哈希不变；原目录未改动。离线重放/验证为 47.755 秒、索引构建为 9.888 秒。所有在线样本确认索引命中，没有偷换成在线原始重放。

**生成变快，但这两个案例仍没有获得相对全量的在线收益。** `adder_shared` 仍在 32 次扩区预算后回退整个模块，复用门数为零；不能将其称为细粒度成功复用。前后两版交付网表的全部单元类型、参数、连接与模块端口逐项一致。

### 选区内部进一步归因

`adder_shared` 在网表生成截止之前，完整契约构建从 **644 次降为 3 次**，逐 cell 来源路径检查从 **23,727 次降为 855 次**。32 次输出闭包预览总计约 0.584 秒；原来每轮都要生成、合并随后丢弃的完整证据。

在线旧源码降级只有一次，SAT 也只有一次：优化前分别约 0.092 / 0.357 秒，优化后约 0.098 / 0.391 秒。两者未改变次数，没有靠取消证明来减少选区成本。生成后的独立复核不在这些数字内。

原最主要热点是每个输出独立扫描整组转换边、反复解码共享祖先，以及大量契约序列化。优化后的来源扫描同时处理全部输出，仍保留原逆序事件语义和每个输出的证据列表。局部函数证明、SAT 和 `proc` 不是此前数百秒开销的主要来源。

## 实现与验收

1. `rtlil.changed_ranges` 逐行比较共同前后缀，只将不相同的中段交给原差分算法。adder 的 25,686 行规范化记录实际只需匹配 1 行中段；模块指纹和结构变化判定不变。
2. `contracts.output_associations` 用每输出一位的集合执行同一轮逆序边扫描；随机包含重复边、逆序关系和重复关联的用例与旧独立扫描逐项一致。
3. `statements.close_missing_outputs` 先预览电气闭包并保留 32 次预算；中间区域不授权替换。能绑定后仍通过完整来源、全部输出、共享消费者和拼接验证；不能绑定就按原规则后备。
4. `Network.observe_unchanged` 只用于验证过作用域和基准的空 delta；检查点和有变化快照继续完整验证。损坏 PI、输出、基准、作用域、删除和扇入的负例均保留。

最终实现完整回归 **384 项通过，零失败、零错误、零跳过**。包含真实 full/delta 逐快照一致性、损坏证据、扩区、跨实例、全部输出、最终交付等价等验收。384 是仓库测试项数量，不是 384 个 EPFL 电路。

本轮没有放宽支持范围或降低候选证据要求，没有补齐全部 ABC 因果历史，也没有关闭交付验证。

## 复现与后续

原始结果在 `runs/cost-attribution-20261102/`：`report.json`、`stages.csv`、前后逐事件 `profile/events.jsonl`、CPU 采样 `profile/profile.json`、最终网表、全量时间戳日志和 `final-regression/report.json` 均保留。已有对比目录没有覆盖。

```bash
# JOB.json 沿用 incremental.experiment_worker 的任务结构；任务输出目录必须是新的。
python3 -m incremental.profile runs/your-job/job.json \
  --profile-out runs/your-job/profile --timeout 360
```

`profile.json` 的 `wall_s` 含子调用，`exclusive_s` 扣除子跨度。`summarize.py` 以完整网表写出为截止点，裁剪跨度并检查独占时间之和；超时任务留下 begin/end 事件和失败信息。正式性能测量不启用此适配器。

下一步优先减少全设计规范化、来源查询/序列化及索引写入成本，并考虑基于便宜信息的及时全量回退。失败尝试加全量的总成本要单列。更大纯组合案例及固定修改区域的规模阶梯放在下一阶段；寄存器边界需另行定义状态身份和下一状态证明，不在本轮同时扩大。
