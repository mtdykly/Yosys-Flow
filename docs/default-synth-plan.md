# 目标：默认 synth 结束后的通用门级网表来源查询与导出

**本阶段的最终终点固定为：Yosys `0e82bbefe` 默认 `synth -top <top>` 全部结束后，与具体工艺库无关的通用门级网表，包含细粒度通用逻辑门和触发器等单元。** 范围包含默认 `techmap`、ABC 及 ABC 后的优化和最终检查；coarse 末端、ABC 前或 `synth -noabc` 的结果只能作为中间检查点。

用户指定原始 RTL 的源码位置及实例上下文后，系统应返回具有来源证据的最终网表对象，并导出带边界端口的子网表。Liberty 标准单元映射、RTL 差分、增量重综合和网表拼接不属于本阶段验收范围；这些研究保留在 [roadmap.md](roadmap.md)。完成来源查询与导出，不要求同时完成安全替换逻辑的证明，`safe_for_incremental_reuse=false` 可以继续保留。

**当前实现状态：** M0 受控 `opt_merge` 闭环已实现；原生流程已接入 AST 身份、部分 process/基础优化、连接迁移、ALU/MACC 替换、techmap 拆分和 ABC 区域交接。`--flow synth` 已实际到达默认 synth 最终门级终点，并支持查询和导出；来源仍为部分覆盖，process 和 ABC 的结果保留候选精度。层次、memory、FSM 等完整来源和 ABC 内部精确定位尚未实现，不能将执行到终点视为 M1–M4 全部验收完成。使用和已验证范围见 [native-synth.md](native-synth.md)。

## 查询集合的定义

默认查询返回：**从所选源码语句或表达式的实例化对象出发，沿已记录转换关系得到的末端来源关联对象集合。** 此集合不保证是唯一、最小或被该语句独占的一块电路。

具体规则如下：

1. 先确定源码版本、文件、语句/表达式身份、范围与实例上下文，再追踪对象演化。同一行有多个表达式时应能分别选择；仅按行查询时需报告实际选中的起点。
2. 拆分保留一对多关系，合并保留多来源。共享 cell 在集合内只出现一次，但保留它的全部已记录来源及外部使用者。
3. **只有来源证据才能把对象加入默认集合。** 电气连接用于计算边界，不用于自动递归加入所有上游驱动。控制条件和数据表达式分别记录来源角色；不能只因为存在电气依赖，就把上游门当成该语句的来源对象。
4. 对应物可以是 cell、连接或常量。没有硬件对象时，只有存在明确证据才能返回“已消除”或“未生成”及其原因；缺失来源应返回“未知/来源缺口”，不能以空 cell 列表代替结论。
5. 导出器从所查询阶段的同一份网表复制对象及必要的连接，按集合与外部的实际连接建立端口。共享和边界说明与网表一起输出。

例如：

```verilog
assign y1 = a & b;
assign y2 = a & b;
```

若合并为一个 AND，查询任一语句都返回该门，并说明另一个来源及 `y1`、`y2` 两处使用关系。

```verilog
assign t = a & b;
assign y = t ^ c;
```

若这两个运算在查询终点仍各自保留，查询第二条语句只选择 XOR，把 `t` 和 `c` 作为边界输入。若后续转换把两个运算共同改写，则按实际转换证据返回对应集合，并报告关联精度。“完整扇入锥”应作为未来单独的模式，不能悄悄改变默认来源选择规则。

## 结果中的覆盖与精度

**追踪覆盖与关联精度必须分别报告。** 一个步骤可以完整记录了区域输入输出，但仍没有足够证据定位区域内每个 cell 的来源。

| 维度 | 需要表达的内容 | 对验收的含义 |
| --- | --- | --- |
| 追踪覆盖 | 对指定输入结构、运行、步骤和查询路径，哪些转换有记录，哪些有缺口 | 全路径覆盖才能宣称该查询没有未记录阶段；运行完成状态另行保存 |
| 关联精度 | 有逐 cell 转换证据的关联、保守区域候选，或未知；连接另报位/范围精度 | 区域候选不能计为精确 cell 定位完成；cell 级来源也不自动等于位级逻辑依赖证明 |

精度应能落到返回对象及证据路径上；同一查询混合多种精度时应分别列出精确部分、候选区域和缺口。当前的 `granularity=cell`、`capture=instrumented` 或单个 `coverage` 字段都不足以独立证明端到端选择精确，这套结果约定需要后续实现。

对 ABC 等多对多变换，必须保存真实区域边界和成员。把区域内每条语句都关联到区域的全部门，只能作为保守候选成果。**即使这样的候选覆盖所有真实对应物，也不能通过精确来源选择的最终验收。**

## 综合配置约束

默认 synth 包含 ABC，执行 ABC 不等于映射到具体工艺库。本目标没有额外指定 Liberty 映射。LUT、`-flatten`、`-noabc` 等选项属于另外的流程配置；开发时可以用它们隔离问题，但不能用其结果替代默认 synth 终点的验收。

默认 synth 保留的模块层次必须得到实例级追踪，不能为简化记录而暗中改成全 flatten。每次运行仍应固定工具和 ABC 版本、实际脚本、源码及 include 摘要、宏、顶层、参数和所用映射资源。

## 固定版本的阶段清单

以本仓库 Yosys `0e82bbefe` 的本机 `help synth` 为准，主要顺序如下。组合命令还会调用子 pass，表格不表示只插桩这些外层入口就能完整记录。

| 阶段 | 默认流程中的主要命令 | 需要的事件 |
| --- | --- | --- |
| 读取和层次 | `read_verilog`、`hierarchy -check` | AST/实例对象、参数派生、信号和单元生成 |
| coarse 开始 | `proc`、`opt_expr`、`opt_clean`、`opt -nodffe -nosdff` | process 到 mux/FF、常量替代、删除、合并、连接改写 |
| coarse 中段 | `fsm`、`opt`、`wreduce`、`peepopt`、`opt_clean` | 状态机提取/重编码、位宽变化、局部模式替换 |
| coarse 后段 | `alumacc`、`share`、`opt`、`memory -nomap`、`opt_clean` | 多算术对象合成、资源共享、memory 端口和状态转换 |
| fine 前段 | `opt -fast -full`、`memory_map`、`opt -full`、`techmap`、`opt -fast` | memory 展开、单元拆分、模板实例与位连接对应 |
| fine 后段 | `abc`、`opt -fast` | Yosys→ABC→Yosys 三段对应及映射后优化 |
| check | `hierarchy -check`、`stat`、`check` | 最终结构、层次和覆盖汇总 |

`opt`、`proc`、`memory`、`fsm` 都应展开核对内部实际调用。先通过小设计走过部分阶段，只能证明该设计触发的变换得到覆盖；不能据此标记任意 RTL 完整受支持。

## 分阶段交付与验收

每一阶段都必须走通“原始源码选择 → 该阶段末端对象 → 带边界端口的文件导出”，并分别通过下文的三层检查。阶段产物必须写明真实终点，不能提前称为默认 synth 最终网表。

| 里程碑 | 查询终点 | 必须声明的支持范围 | 端到端验收 |
| --- | --- | --- | --- |
| M0，已实现的受限版本 | `opt_merge` 后 | 单模块简单组合表达式；以 `src` 范围为起点 | 两处来源合并、同一行表达式区分、共享使用说明、来源集合边界及 cell 子网表导出 |
| M1，下一阶段 | `proc` 与基础优化后，锁定具体 pass 列表 | 最小前端语句/表达式身份；直接赋值、常量赋值、组合 `always`、条件赋值、简单寄存器及已声明的复位/使能/初始化形式 | 无 cell 语句也有有证据的查询结果；mux/FF 的来源正确；按时序约定导出；常量化和删除有原因 |
| M2 | 默认 coarse 阶段结束 | 逐项声明算术、层次实例、FSM 和 memory 的支持形式及限制 | 每种已支持转换都能从源码查询并导出；跨实例不混淆，未支持形式明确返回缺口或拒绝 |
| M3 | 默认 fine 流程中 ABC 前的检查点，包含 techmap 及其后、ABC 前的优化 | 已支持粗粒度单元的 memory_map/techmap 拆分和随后的优化 | 宽运算一对多拆门后，来源选择不漏门、不无依据地加入无关门，位连接与边界正确 |
| M4，最终终点 | 默认 `synth -top <top>` 结束 | 声明范围内的完整流程，包含默认 ABC 及其后优化、检查 | 查询到最终细粒度通用逻辑门/触发器，三层检查通过；精确关联、区域候选、来源缺口分别报告 |

M4 的精确定位验收不能由区域候选替代。某类 RTL 只有区域级结果或来源缺口时，应保留为部分支持，不纳入“该类结构已经完成精确来源查询”的声明。任何阶段都不能用未触发复杂变换的几个例子推断任意 RTL 已受支持。

## 实现顺序与近期工作

### 当前实现进度：原生检查点与默认 synth 候选闭环

已提供 `make native` 和 `run --flow m1`，在固定版本原生 Yosys 中接入简化前 AST 身份、cell/赋值生成、process 目标信号与临时信号对应、初始化、普通 `proc` 子步骤以及普通 `opt_merge`。当前可查询并导出组合 `always`、简单 FF、直接连接和常量；FF 导出保留逐位初始化并增加时序格式检查。

`--flow m1` 保留 `proc -noopt; opt_merge`；`--flow m1-opt` 新增 `proc; opt_expr; opt_clean; opt_merge; opt_clean`；**`--flow synth` 已直接执行默认 `synth -top` 到最终门级终点。** `opt_expr` 记录目标 cell 的替代/删除，`opt_clean` 在删除 wire 前迁移连接身份；`opt_dff`、`alumacc` 和 `techmap` 已记录部分实际目标/模型到生成对象的关系。ABC 保存真实输入成员、边界、调用身份、输入输出网络和脚本，再追踪后续优化。

process 仍为 `process_signal_candidate`，ABC 为 `abc_region_candidate`，整体 `coverage=partial`，M1–M4 的精确验收尚未完成。下一步仍须补齐 AST 简化、逐动作/分支来源、跨 cell 优化依赖及其他 pass；不能把检查点结构观察当作语义证据。构建基础见 [native-m1.md](native-m1.md)，默认终点和当前三层测试见 [native-synth.md](native-synth.md)。

**M1 的首项工作是最小前端来源记录。** 在发生会丢失身份的前端变换之前分配运行内语句/表达式 ID，保存源码摘要、文件、行列范围和上下文，并记录其到 RTLIL 对象的关系。连接、常量与 cell 都是合法产物；`assign y=a` 和 `assign z=1'b0` 必须纳入近期验收，不以解析最终 `src` 属性或在查询时猜测语法作为完整来源证据。同一源语句的不同实例化对象使用不同实例身份。宏、generate、循环/函数展开可以分批扩展，但经过未覆盖展开的查询须报告缺口。

**同时把记录器接到正常 Yosys 调用链。** 当前 `trace_opt_merge` 适合验证方案；下一步建立固定版本的 Yosys 源码补丁和构建方式，将钩子接回原生实现，使正常 `synth` 内部调用也被记录。自定义命令负责开关和导出，语义事件仍在实际转换处产生。不能通过添加 `keep` 等约束改变优化决策来维持来源。

记录器需成为公共库接口，统一管理创建、变更、重命名、复制、删除及多对多替换。内部句柄必须显式维护生命周期，避免地址重用或同名再创建继承旧身份。步骤应有父子关系，区分 synth/opt 包装步骤与具体子 pass，同一事件只记录一次。

**随后打通 proc、opt_expr、opt_clean 及基本 opt 的 M1 闭环。** 每接入一种变换就增加其来源选择和导出案例，分别追踪条件、赋值、状态更新和简化后的对应物。删除保留原定义及理由。只有对应事件、边界处理和测试落实后，才能逐项解除当前 process/FF 拒绝条件。

M2、M3 按固定流程逐步覆盖算术、共享、位宽、FSM、memory、实例与 techmap。一对多拆分需要端口/位对应，多对多替换必须标注实际关联精度。完整参数条件依赖继续服务于后续增量失效分析，不要求先实现 RTL 差分或重综合调度。

M4 的每次 ABC 调用使用独立 invocation_id，记录 Yosys 导出网络、ABC 内部改写/映射、重新导入三段关系，继续追踪后续 opt。区域候选可以用于调试交接，但只有更细的来源证据和独立精度测试通过后，才能升级为 cell 级定位成果。

## 实例与时序导出约定

**实例：** 查询身份包含顶层起始的完整实例路径及参数派生上下文。相同模块实例化两次时，指定 `top/u0` 不能混入 `top/u1` 的使用者或边界，即使二者共用同一综合后模块定义。未指定实例且存在多个上下文时，应要求限定实例，或按实例分组返回；禁止静默合并。跨层次对象需通过实例端口映射计算边界，尚未实现的跨层次导出应明确拒绝。

**时序默认规则：** 默认来源集合包含被所选语句的转换证据关联到的 FF/状态单元。导出这样的集合时必须保留这些单元，不得自动改成组合逻辑。状态单元的时钟、复位、使能端口和极性/取值参数、D/Q 连接，以及相关 wire 上逐位的 `init` 信息都须保留；缺失的初始化不能被擅自补为 0。控制端的外部驱动成为边界输入，不因此递归加入其整个逻辑锥。wire 切片、别名合并和重新命名时都要检查初始化位的对应。

若 FF 没有被来源集合选中，其状态输出可作为子模块的边界输入，并标明由外部状态驱动。未来可另设显式的“排除状态单元”模式，将原 Q 侧作为输入、原 D/控制侧按使用关系设为输出，并记录它们与原状态单元的对应；不能把该切割结果宣称为保留了原设计的时序行为。

M1 必须明确支持哪些时钟、复位、使能和初始化形式，验证状态单元包含/未包含时的边界。导出带状态的子模块需要在相同初始化和控制语义下做适用的时序等价检查；现有组合导出的格式等价测试不能独自承担这项验收。仅解除 FF 拒绝条件或沿用当前重建 wire 的方式不足以实现时序支持。

## 三层独立验收

| 层次 | 要验证的问题 | 必需证据 |
| --- | --- | --- |
| 转换记录检查 | 实际对象的新增、删除、改写、改接是否都被解释 | 对象生命周期和引用检查、事件重放、实际阶段快照/网表对照、未覆盖变换报告 |
| 来源查询检查 | 按上述选择规则，是否漏选或无依据地加入对象，是否混淆实例或夸大精度 | 独立于待测查询算法的预期对象集合或结构/语义断言、逐对象的来源路径、应排除对象检查、覆盖与精度分别核对 |
| 子网表导出检查 | 已选集合的类型、参数、位连接、边界及状态信息是否被保留 | 与原阶段网表逐对象核对、边界检查、重新读取导出文件、适用于组合或时序语义的等价检查 |

**导出等价检查不能代替来源查询检查。** 即使选错 cell 集合，复制和格式转换仍可能等价；因此不得仅凭导出等价通过就认定源码定位正确。预期集合不能由同一个待测来源传播算法自动生成后拿来对照自己。

对于可独立确定预期集合的固定小例子，令预期集合为 E、查询集合为 R，精确定位测试要求 `R = E`，同时检查应包含与应排除的对象。报告漏选和额外选择的对象，而不只比较数量。空集合需要另验“已消除/未生成/未知”的证据。ABC 等不便依赖生成名称的案例，可采用人工审核的最终结构及实例/端点断言；不得通过任意扩大预期集合来容纳粗粒度候选。

近期及后续至少覆盖：

| 案例 | 来源查询必须检查的断言 | 导出必须检查的断言 |
| --- | --- | --- |
| 两条相同表达式 | 两条语句指向同一门，均保留来源 | 门只复制一次，全部外部使用关系可查 |
| 一行多表达式及两级逻辑 | 列/表达式选择不混入邻居；第二级不自动纳入上游 | 上游信号成为边界输入 |
| 直接连接和常量赋值 | 起点有独立语句身份，对应连接/常量或明确消除证据 | 不依赖存在 cell，也能返回合适的子模块/结果说明 |
| 组合 always、条件赋值 | 分支赋值和条件到 mux 的来源符合预先声明的规则 | 数据和控制边界正确，无无关分支对象混入 |
| 寄存器、复位、使能、初始化 | 状态更新对应的 FF/组合逻辑可追踪，未选状态边界明确 | 控制极性、初始化及状态语义保留 |
| 同模块两次实例化 | 限定一个实例不混入另一个上下文 | 实例端口绑定和共享定义的使用关系正确 |
| 宽运算经多 pass 拆门 | 预期后代完整，无关运算的门被排除 | 参数、位序、内部连线和外部边界保留 |
| 常量化或删除 | 消除与来源缺口明确区分，保存原定义和原因 | 返回常量/连接或带证据的消除说明，不伪造门 |
| FSM 和 memory | 对已声明的结构验证多对多关系及精度 | 状态、端口和初始化按支持约定保留 |
| ABC 重写及后续优化 | 不同来源、共享逻辑和无关区域分别检查；区域全部门的笼统返回不能通过精确定位测试 | 导出来自真正的默认 synth 末端，边界与最终网表一致 |

还需比较原版与开启记录的相同综合流程，在相同配置下保持功能一致，记录开关不能改变优化约束。每项里程碑的支持清单应同时列出已验证和未支持的结构；全部触发了哪种变换、实际覆盖到哪一步，要能从运行报告中核实。

## 后续性能与阶段完成条件

来源正确性、终点和支持范围明确后，再测量日志大小、快照、加载、建索引和查询成本；优先按运行缓存已验证索引、减少重复快照。JSONL 继续作为事实记录，不因性能猜测提前换数据库。

本阶段完成要求是：**在声明并验收过的 RTL 支持范围内，正常默认 synth 结束后，源码查询、精度报告和实际子网表导出均通过三层验收。** 部分结构尚有来源缺口或只有区域候选时，必须保留部分支持的标记，不能宣称任意 RTL 精确定位已完成。源码编辑后的坐标转换、增量失效分析、局部综合和安全拼接属于后续研究，不阻塞本阶段独立验收。
