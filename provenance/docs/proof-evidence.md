# 旧设计证明关系的持久复用

来源记录仍是主体。`verified-index.sqlite3` 保存来源、版本、转换边和查询关系；新增的函数证据库保存已经证明的 ABC 入口与出口函数对应、极性和依赖。它不把候选来源升级成完整因果历史。

## 两类可以复用的证据

1. **函数关系。** `functions.sqlite3` 保存规范化后的函数类、入口/出口节点、网络连接及公共源码锚点。实际复制、求解器成功记录、映射见证和局部证明经检查后才能进入这些类。在线使用有界缓存和 SQL 索引，避免重新解析全部检查点、重建完整表达式代数和重复全局归并。分批准备时，每次发布写入独立的 `generations/<id>/functions.sqlite3`，顶层 `manifest.json` 指向当前完整版本。
2. **完整旧区域。** `regions-<函数库摘要>.sqlite3` 保存已经闭合全部对外输出、完成独立旧 RTL 证明的区域。每个条目独立签名，绑定函数库和旧建档身份。再次选中已覆盖的操作时，可复用该区域；不同修改也可用相同函数关系组合新的边界。新组合仍需检查全部外部输出，不能把两个已证明区域的边界直接拼在一起。旧式单次发布库仍使用 `regions.sqlite3`；函数库更新后，不自动沿用旧版本的区域缓存。

两个库位于旧归档之外，不复制原始 JSONL、最终网表和整个来源索引。原归档保持不变。函数库的描述符绑定实现指纹、旧 manifest 摘要、数据库摘要和本机认证密钥；密钥不归档。换基准、改数据库、损坏区域条目或改变证明实现会拒绝使用，不能只重算普通摘要来获得认证。

## 第 4 步：接入重放与建索引

新建档使用 `run --prepare-evidence`，未完成捕获使用 `resume --prepare-evidence`。`abc_internal.analyze()` 将本轮已解析的网络和已确认的端点函数关系直接交给证据准备器：检查点材料共享这份解析结果，已证明的端点等价直接合并函数类，不对同一个关系再次求解。其他尚未证明的关系继续检查，不因为共用解析数据而升级精度。

来源索引完成后，函数库使用同一个已经验证的设计视图，不重新加载归档、重放日志或恢复整个查询索引。实际顺序是：重放与共享检查点材料 → 来源索引 → 基础函数库与旧源表示 → 通用检查点边界扫描；不是把全部增强证明塞入插桩综合。`--refine-outputs` 仍是单独、可恢复的增强任务。

已经完成的旧归档可以重建索引并准备证据：

```bash
python3 -u -m yosys_flow reindex runs/old-run \
  --out runs/reindexed --prepare-evidence
```

`reindex` 在新目录复制原始材料、按当前实现重新重放和核对已有原版网表及验证材料，再写新索引；它不重跑插桩或原版的完整 `synth`，也不要求旧插桩二进制仍存在。源代码当前工具与旧捕获工具不同时，不应绕过 `resume` 的身份检查。`reindex` 只接受已完成的原始归档，不接受不完整捕获或按目标细化的派生归档。旧归档不变，复制成本与新增体积都计入离线准备；已有验证策略中的跳过项仍保留。

旧的重放接口升级需要通过 `reindex` 一次性升级来源索引。之后仅改进函数证据准备时，可以复用这个来源索引，另建新的证据目录；不应继续恢复不同证明实现生成的旧证据目录。当前检查点扫描和 FRAIG 导入没有修改来源索引的语义指纹。

`relations/` 保存统一的证据描述，定位回原始来源索引，避免展开所有来源大集合：

| 类型 | 含义 | 可以直接当作函数等价吗 |
|---|---|---|
| `source_association` | 记录的来源关联、候选区域 | 不可以 |
| `rule_checked_transform` | 已检查事件输入输出、对象版本、连接和规则约束的变换 | 不可以据此声称通用函数等价 |
| `function_equivalence` | 已验证的独立门切点、门组或端点函数关系，保留作用范围和极性 | 只能在其已证明的范围内使用 |

Yosys 的规则事件与 ABC 的函数证据使用相同描述字段，但不混为一类。没有为每个 Yosys 对象额外运行 SAT。共同改写的门组仍标为 `joint_group`，不伪造组内逐门归属。

第一次加载仍会校验数据库摘要，成本随文件体积增加；“按需查询”不等于完全没有加载或完整性检查成本。每个读取器的节点、用户、函数类缓存各最多 8192 项。

## 不预知修改的准备方式

先有完整旧建档，再执行：

```bash
python3 -u -m yosys_flow prepare-evidence runs/old-run
```

默认创建 `runs/old-run.proofs/`，只接受旧建档，不接受新版 RTL、行号、目标信号或待替换区域。它先发布端点的结构恒等关系，然后逐阶段检查并安装旧设计的复制、改写、映射等证据，每完成一阶段便保存状态、发布新的查询库。无需等待全部输出的增强证明结束。`--structural-only` 只保存结构恒等关系，主要用于诊断，覆盖更窄。

普通准备还在 `source/` 保存从归档 `frontend.il` 降低得到的组合表示、源信号锚点、驱动关系及 SQL 索引。这里运行一次 `proc; opt_expr; techmap; opt_expr; opt_clean`，不运行 ABC 或完整 `synth`；工具默认上限 600 s，可用 `--source-timeout` 修改。此表示绑定旧归档、前端摘要、工具和实现，不能当作等价证明。在线按边界读取相关单元，避免每次重跑旧前端转换和扫描全部源单元；新的独立边界仍需证明。`--structural-only` 不执行这项准备。

通用准备默认增加三项与修改位置无关的工作：

- 导入固定 ABC 版本中已记录、且被 `fraig_sweep_copy` 实际采用的 FRAIG 成功等价合并。核对来源快照、命令、采用后的极性和 cleanup；与 DCH 一样，这是成功求解结果的复用，不是重新调用 SAT，也不是完整历史的声明。集成建档直接复用本轮解码数据；独立准备只额外读取到 FRAIG 结束的日志前缀。
- 补证旧重放报告中的未知改写事件。候选来自旧日志的 `unknown_rewrite_examples`，先核对实际替换事件与所属快照，再以该快照全部 PI 独立取值为条件比较替换前后函数。每次 CEC 默认 20 s，整批协作式预算 300 s；失败、超时、超预算继续保留未知。原报告只保存有限数量的未知样本，超过清单容量会明确报告 `inventory_truncated`，不会宣称已检查全部改写。成功关系保存为共享表达式 DAG 和带事件身份的等式，随后与其他证据统一传播；这一步发生在新 RTL 到来前，不接受修改位置。集成重放复用已解码快照；独立准备只解析到最后一个待补事件。
- 按顺序扫描所有相邻旧检查点的全部节点。先用已证函数类切割，再对候选做有界局部函数证明；每段确认的关系通过统一表达式和同余闭包传播至最终入口/出口类。扫描默认每侧最多 64 个节点，单次 SAT 子进程最多 50 ms，阶段总预算默认 600 s。模拟签名只提候选，不证明等价；不会调用整网 CEC，也不接收修改行号或候选对。

FRAIG 导出只扫描一次事件清单，按 ABC 调用索引 sweep、按前驱网络索引 cleanup，每次调用只创建一次复制映射。共享节点存储可直接确认结构相同；不同 `SnapshotMap` 不可变版本按对象身份隔离比较缓存，普通可变字典不使用跨关系缓存。表示类型及 PI/PO 次序仍逐条比较，节点存在、事件先后、命令身份和采用极性也逐条检查。进度分为 `fraig_evidence_load/index/validate/write/complete`；`checkpoints.json` 的 `fraig_export_statistics` 保存事实数量、扫描数量、结构构造/复用次数及分阶段秒数。优化没有更改证据规则或把未证明关系升级为等价关系。

扫描前先统一 SOP 与映射门的局部函数表达。`exhaustive_gate_function_dag_v1` 对每个门至多 6 个独立操作数枚举完整真值表，处理常量、反相、重复操作数及无关操作数，再从共同 PI 开始组合函数 DAG。相同形式是已检查的结构恒等，不靠随机模拟或节点同名判断；超过操作数上限的节点保留各自作用域，不伪造对应。这个规则可以直接连接 `.names` 形式的 NAND/XNOR 与导出 BLIF 中的 `.gate` 形式，避免因表达形式不同而反复展开巨大的输入锥。其结果与局部证明一起写入函数类，检查点报告中的 `gate_forms` 给出规则、合并数及未处理门数。

扫描每个检查点后将小型证明日志写入 `work/boundary-*.json`，摘要由认证状态文件绑定；不为每个门重复保存整个证明器。正常结束或协作式预算停止时保存一次完整状态并发布新的函数库。恢复时可重放已认证的日志，未完成检查点继续扫描。损坏、换基准或换实现均拒绝复用；不能自行编写节点对冒充证明。

未知改写补证保存于 `checkpoints-*/recovered-rewrite-functions.json.gz`，摘要与准备见证绑定。报告列出候选数、实际尝试数、成功数和未解决事件。一次未知不能当作不等价反例；扫描完成也不能替代区域全部输出的证明。该批计算计入 `base_evidence_seconds`，单事件进度计时包含结果编码，不是纯求解器时间。

`--boundary-budget 600` 控制本轮通用扫描预算，`0` 表示不限；预算是协作式检查，当前局部计算、同余闭包和提交会带来超出。`--no-boundary-scan` 可用于对照诊断。`run/resume/reindex --prepare-evidence` 同样默认执行扫描。`--structural-only` 不导入求解事实，也不运行该扫描。

报告分列 `boundary_scan_seconds`（扫描、组合和小日志提交）与 `boundary_commit_seconds`（阶段末完整状态和库发布）；后者包含对应的状态保存/发布子项，不重复相加。`boundary_scans` 给出各检查点的未匹配数量、节点样本和失败原因。`complete` 只表示已扫描该阶段，不能理解成全部内部节点都有精确对应。消失的内部切点允许通过门组闭合全部对外输出；仍无证据的节点保留未知。

基础准备完成后，可继续增强：

```bash
python3 -u -m yosys_flow prepare-evidence runs/old-run \
  --resume --refine-outputs --enhance-budget 3600 \
  --batch-outputs 8 --cache-engines 1
```

`--refine-outputs` 分批尝试全部旧输出中的缺失边界，每批默认 8 个输出。`--enhance-budget` 是本次命令的增强阶段预算，默认 3600 s，`0` 表示不限制；不包括归档加载和基础证据准备。预算在证明入口和进度回调检查，正在执行的一次求解或状态写出可能使墙钟超出预算，外部 `timeout` 才是整条命令的上限。

`ready` 表示所请求工作完成，不能推断每个内部切点都已证明；失败或未知的输出也保存尝试结果。预算耗尽、Ctrl-C 或 SIGTERM 中断后，有已发布库时报告 `base_ready_partial`，仍可查询已证明关系，缺失关系继续保守处理。多个 ABC 调用的处理中断时，可能只有部分调用已发布；描述符列出实际覆盖的调用。`report.json` 是最新一次运行，`report-<id>.json` 保留每次运行的计时，`progress.jsonl` 附会话 ID 和时间戳。

## 检查点、恢复与计算共享

`--resume` 必须指向同一个输出目录；自定义目录时两次均传 `--out PATH`。准备过程的检查点保存在 `work/`，包括端点及各相邻 ABC 网络的表达式、函数类、极性、尝试缓存、已检查见证和已完成输出。状态使用数据型 SQLite 序列化，描述符认证旧归档身份、证明实现、策略及数据库摘要。恢复后直接加载状态，不重新构造已经保存的函数代数。没有认证状态的历史超时目录不能直接续接，仍可用原来的完整旧建档在新目录准备，无需重跑综合。

跨检查点的证明器按相邻网络对复用。默认内存只保留一个，可用 `--cache-engines` 增加；被换出的状态写入磁盘，后续输出或进程恢复时加载。同一对网络不再对每个输出重复安装相同见证和做初始函数归并。保存的只有无条件成立的关系，临时切点假设不进入已发布库。`checkpoint_stats` 和 `bridge_stats` 报告构造、恢复、缓存命中及状态读写开销。

发布采用不可变数据库加原子替换描述符：后续增强失败，不会改坏上一份可查询库；已经打开的读取器可继续使用旧版本。目录锁阻止两个准备进程同时写入。成功批次保存 `batch-<id>.json`，摘要和已尝试输出写入认证状态；中断的当前批次可重试，前面完成的批次跳过。刚完成但尚未保存的工作仍可能丢失。

这会增加磁盘空间和状态写出成本。旧发布版本暂不自动回收，避免破坏已有读取器；每次发布仍写完整查询库，并非增量数据库更新。缓存上限只限制跨检查点证明器，其他图和见证仍可能占较多内存。集成路径共享解析和验证结果；跨检查点剩余证明、SQL 写出和旧源降低仍有成本，不能仅因合并命令就声称这些计算已消失。

## 第 5 步：在线局部补证与明确阻塞

新版到来后，照常运行：

```bash
python3 -m incremental auto \
  --base-run runs/old-run --new-source path/to/new.v --out runs/edit
```

工具自动发现 `<base-run>.proofs`。若准备时指定了其他输出目录，使用 `--proof-evidence PATH`。该参数是旧证据的位置，不是提前提供修改信息。原有 SQLite/gzip 来源索引都可作为基础；当前函数区域的自动组合限于已经支持的**单模块组合操作**，层次设计仍走原选区与验证路径。

在线步骤：从新旧差分得到修改种子 → 经 AST 创建边和来源边到达 ABC 入口 → 查询已证函数关系 → 闭合实际边界及全部对外输出 → 校验旧 RTL 的局部功能 → 持久保存成功区域 → 提取新版 patch、局部综合和拼接。完整旧区域命中时省去其中重新组合和求解的步骤。

旧源区域检查的比较双方是**旧 RTL 在选定独立边界上的函数**和**旧最终门区域在相同边界上的函数**。它不是证明新版等于旧版；新版允许有真正的功能变化。

`incremental auto` 默认 `--region-proof-budget 60 --region-node-limit 4096`。前者是本次在线旧区域补证共享的墙钟预算，包含边界函数检查及旧源局部电路构造、miter/SAT；后者限制受影响 ABC 图、局部源电路、最终选区和相关函数遍历的规模。来源遍历另按该上限的 16 倍限制访问边数，仍保留原先的事件先后约束。局部 SAT/工具调用受剩余预算约束，增强阶段使用的全局 CEC 不会作为在线查库的隐含后备。

小范围缺口仍可沿现有规则扩区；范围或共享预算超限会返回 `blocked`，包括 `old_region_node_limit`、`old_region_provenance_traversal_limit`、`old_region_proof_budget_exhausted`、`old_region_tool_timeout`，并报告关系阶段、窗口/节点数和未证明状态。不会通过跳过检查交付网表。预算可显式调大，但应结合缺口记录判断是否需要补钩子。证据库缺失时原有来源选区仍可使用，同样受上述在线限制。

这些预算独立于 `--whole-equivalence-timeout`；生成候选后的整网验证仍单独计时。必要局部证明仍属于在线生成成本。

## 已有细化任务不再丢掉证明状态

现有 `refine_partitions.py` 可以在得到关系后直接写函数库：

```bash
python3 provenance/tools/refine_partitions.py runs/old-run \
  --input-wire target_signal --out runs/refinement \
  --checkpoint-bridges --recorded-rewrites \
  --evidence-out runs/old-run.proofs
```

不需要加 `--publish`，也不需要复制整份旧归档。完整旧区域证明成功后，还会保存相应区域条目。旧的 `--publish` 仍兼容。

**此命令用到了指定目标，不能记作未知修改实验中的通用离线准备。** 描述符记录 `target_independent=false`，自动增量报告保留 `preparation_scope`。`prepare-evidence` 则记录 `target_independent=true`。已经完成的历史任务只有 JSON 证明摘要、没有规范化函数库时，首次转换仍有一次准备成本；不能把未认证的 `pairs.json` 当成可直接信任的函数库。

## 计时口径

| 位置/字段 | 内容 | 是否计入未知修改的在线时间 |
|---|---|---|
| 准备报告 `archive_load_seconds` | 旧归档身份核对、来源索引读取 | 通用旧证据准备时不计；在线再次加载要计 |
| 准备报告 `base_evidence_seconds` | 旧端点函数构造或恢复、检查点证据处理与基础库发布 | 不依赖修改的准备不计 |
| 准备报告 `typed_evidence_seconds` / `source_preparation_seconds` | 类型描述写出、旧源表示降低与索引 | 不依赖修改的准备不计 |
| 建档/重建报告 `proof_witness_capture[_seconds]` | 共用重放过程中导出检查点和验证材料 | 已包含在记录验证/重验证阶段，不重复相加 |
| 准备报告 `enhancement_seconds` | 所有旧输出的分批细化、状态保存与发布 | 不依赖修改的准备不计 |
| 准备报告 `publication_seconds` | 写函数库，检查并签名发布；已包含在上述两个阶段中 | 通用旧证据准备时不计，不重复相加 |
| `checkpoint_stats.state_save_seconds/state_restore_seconds` | 恢复用完整状态的写入/读取；也是上述阶段的子项 | 通用旧证据准备时不计 |
| 增量报告 `proof_evidence.metrics.authentication_seconds` | 验证持久证据库身份与摘要 | 计入，已包含在基准加载时间中 |
| `proof_evidence.metrics.region_preparation_seconds` | 请求区域的查库、闭合、绑定、必要证明及条目保存 | 计入，已包含在选区时间中 |
| `proof_timings.boundary_function_proof_seconds` | 本次 ABC 局部独立边界上的 BDD/SAT 函数检查 | 必要证明，计入在线时间 |
| `proof_timings.old_source_cut_proof_seconds` | 旧 RTL 局部语义准备和独立全输出证明 | 必要证明，计入在线时间；不是纯 SAT 求解器时间 |
| `proof_timings.old_source_representation_seconds` / `old_source_cut_assembly_seconds` / `old_source_miter_and_sat_seconds` | 旧源表示获取、局部电路构造、miter 与 SAT 工具执行 | 上一行的子项，不重复相加 |
| `proof_evidence.metrics.phase_seconds` | 查缓存、来源到 ABC、局部边界、最终绑定、旧源证明和保存 | 区域准备内部互不重叠的阶段；与其他证明子项有包含关系 |
| `proof_timings.old_source_certificate_lookup_seconds` | 完整旧源区域证据命中后的绑定检查 | 计入在线时间，未重新求解 |
| `timings.required_old_region_proof_seconds` | 上述边界函数证明与旧源区域证明的合计 | 在线选区的子项，不能再次加到总时间 |
| `timings.netlist_generation_seconds` | 新 RTL 到完整候选网表生成，含在线必要证明 | 主要增量时间指标，不扣除证明 |
| `timings.post_generation_validation_seconds` | 候选生成后独立全量参考、整网等价及重读验证 | 单列审计时间 |

`equivalence_precheck_seconds` 仍单独报告，用于判定功能不变修改能否复用；它也属于在线决策成本。所有包含关系都不能重复相加。

系统成熟后，可研究将独立全量参考和整网等价作为可配置审计。但当前用来弥补来源缺口、确定边界安全性的证明仍是算法的一部分：只有由绑定一致的既有证据替代，才可以省掉重新求解。本轮没有增加关闭这些检查的选项。

## 第 6 步：首次修改与重复修改分开测量

准备只输入旧归档，不传目标信号或历史候选。准备结束后，再给 `incremental auto` 完整新版 RTL。首次运行应使用新证据库，检查 `proof_evidence.metrics.initial_region_cache_entries == 0`；重复同一修改另建运行目录，报告已有缓存条目、`cache_hits` 和新增区域数。函数证据和旧源表示属于通用离线数据，区域证书属于修改发生后的缓存，二者不能混淆。

分别记录离线准备、`netlist_generation_seconds`、其中的 `required_old_region_proof_seconds`、生成后的 `post_generation_validation_seconds`，以及重复运行的上述数据。不把必要证明从在线总时间中扣掉；状态为 blocked/failed 时不能当作成功增量样本。完整 hyp 命令见 [实验说明](../../experiments/docs/hyp.md)。本轮实现验收包含旧设计通用准备和边界诊断，未重跑完整 hyp 在线增量流程。

## 缺口和验收

`proof_evidence.metrics.misses` 区分前端操作到 ABC、ABC 独立边界、ABC 到最终门绑定、旧 RTL 局部功能四个阶段，并保留窗口超限信息。它用于确定下一条确实需要补的来源关系；失败不会保存为成功证据，原有保守扩区/拒绝策略继续生效。

新增回归包含：目标无关准备后处理两种不同修改；重复修改不再次运行旧区域 SAT；大网络中的小目标按需读取；非结构恒等证明跨进程保留；互补边界吸收反相器且覆盖侧输出；未知关系和资源上限；换基准、改实现和证据损坏拒绝。磁盘选区与原内存算法逐项比较证明结果。

11/23 的通用边界与旧改写补证实现通过 **614 项完整回归，零失败/错误/跳过**，729.251 s，报告为 `runs/boundary-forms-regression-20261123/report.json`。其中本轮新增 19 项覆盖相邻检查点闭包、SOP/映射门统一表达、极性、消失切点的门组、随机电路穷举核对、伪候选、预算中断及认证日志恢复、FRAIG 实际采用与未知改写补证。后者仅接受实际旧事件和所属快照；无法证明的候选不得进入函数类。

hyp 的最新算法验收先从旧检查点通用重建函数关系，再查询原失败位置，得到 6 门、5 输入、2 输出的闭合区域，全部外部输出通过独立边界校验。报告为 `runs/hyp-boundary-generic-20261123-063517/gate-form-acceptance.json`；没有目标专用缓存，也没有将历史候选对注入准备。它验证的是 ABC 边界能力，尚非完整新版增量生成与整网验证；正式库还需按当前实现发布后才能交给在线命令。

第 4–6 步实现后的完整回归为 **595 项通过、零失败/错误/跳过**，耗时 **717.707 s**，报告为 `runs/proof-pipeline-final-regression-20261122/report.json`。本轮新增 15 项测试，覆盖共享重放与独立准备结果一致、已完成归档重建、捕获续建、证据类别隔离、认证材料损坏拒绝、层次模式、小目标按需读表、在线预算阻塞和首次/重复修改。256 位案例中的单门切割读取少于 10 个单元、20 行驱动和 20 行别名；错误局部函数仍被 SAT 拒绝。这是功能及读取范围验收，不是 hyp 性能结果。

前一轮分批恢复的完整回归为 579 项通过、零失败/错误/跳过，约 695.7 s，报告为 `runs/proof-resume-regression-20261122/report.json`。随后补齐基础准备中断的计时并增加一项测试，21 项专项回归全部通过，记录为同目录的 `resume-followup.json`。两次测试有重叠，不能将数量相加作为完整回归数。

前一轮新增的 6 项恢复测试覆盖发布失败保留旧状态、损坏及错误基准拒绝、桥接证明器换出与跨进程恢复、批次中断后跳过已完成输出、预算耗尽后继续，以及基础准备中断的计时和恢复；恢复结果与不间断执行逐项比较。

用户运行的旧版 hyp 准备曾在 7200 s 超时，未发布函数库。11/22 已完成基础准备，但首次修改仍因缺失边界阻塞；11/23 的中间版本通用准备完成于 2955.52 s，仍不能据此宣称局部边界全部闭合或首次增量成功。旧 RTL 的公共组合表示可以离线准备；IR 差分、局部电路装配、缺失关系证明以及最终网表绑定仍有在线成本，后续按分项继续优化。当前验收、具体限制和命令见 [hyp 实验](../../experiments/docs/hyp.md)。

可查看上一版保留的 `runs/proof-evidence-demo-20261122/summary.json` 小型闭环结果：先准备旧证据，再测试两种不同修改、重复修改及两处同时修改，四项均通过。首次两项各生成一个新区域证据；重复修改命中一个、两处同时修改命中两个；后两项没有再次运行旧区域函数证明。该示例与当时回归并行执行，仅用于说明报告字段及正确性，不作为性能基准，也不作为当前实现可直接加载的证据库。完整历史报告在 `first/`、`other/`、`repeat/`、`combined/`。
